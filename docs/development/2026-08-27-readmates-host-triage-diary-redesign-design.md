# ReadMates 호스트 워크스페이스 재설계 — 오늘 트리아지 + 모임 다이어리

- 날짜: 2026-08-27
- 표면: Host app (`/clubs/:slug/app/host/**`, 호환 `/app/host/**`)
- 상태: 설계 승인됨 (2026-08-27 — 방향 A+B 조합 및 원장 행 문법 시안 검토 포함)
- ADR impact: **supersede** — ADR-0044 대체, ADR-0045의 host 범위 축소. 신규 `Proposed` ADR-0046.
- 관련: `front/DESIGN.md`, `docs/agents/design.md`, ADR-0044, ADR-0045, ADR-0026, ADR-0038

## 1. 문제

현재 호스트 화면 11개(라우트 12개)는 같은 운영 질문을 여러 화면이 나눠 갖고, 같은 개념을 화면마다 다른 언어로 말한다. 코드 기준 진단:

- **홈 역할 화면이 4개.** 오늘(대시보드), 운영 허브, 모임 목록, 기록 장부가 "다음 모임 / 확인 필요 / 기록 완성"을 분산 소유한다. 운영 허브는 1차 내비게이션에 없어 발견되지 않는다.
- **같은 lifecycle을 다른 라벨로 표현.** DRAFT가 목록에선 "작성 중", 기록에선 "예정", 워크스페이스에선 "모임 작성 중". PUBLISHED는 "공개됨/공개 완료/게시 완료"가 혼용된다.
- **확인 필요 항목이 3곳에 분산.** 오늘(1건 스니펫), 운영 허브(전체), 기록(필터)로 흩어져 단일 처리 큐가 없다.
- **마감·게시 목적지 부재.** `/closing`은 Focus Deck으로 리다이렉트되고, 모임 직후 "마감 보드" 기대를 채우는 화면이 없다.
- **초대·알림이 내비 밖 유령 화면.** 초대는 멤버 탭의 하위 CTA로만, 알림은 "오늘" 탭 current로만 진입한다.
- **페이지 셸 재구현.** editorial ledger / document panel / table+card 이중 UI / 작업대 레이아웃이 화면마다 다르게 손으로 짜여 있다.

리서치 근거(요약): Airbnb 2025 호스트 개편의 "Today = 연대기적 작업 허브, KPI 대시보드 금지", Luma의 "대기자가 있을 때만 존재하는 Pending 구역 + 승인은 통보를 포함한 결정", Ghost Shade의 "페이지 타입 3종(List/Detail/Analytics) + 단일 PageHeader", Substack의 계층 라벨링 붕괴(반면교사), Linear/GitHub의 "읽음 ≠ 처리" 큐 문법.

## 2. 결정된 방향 — A+B 조합

- **홈은 트리아지(A안 "오늘 수첩").** 하루의 단일 처리 큐 + 다음 모임 히어로.
- **모임 상세는 다이어리(B안 "모임 다이어리").** 회차의 생성→준비→당일→기록→게시가 한 화면의 세로 타임라인.
- 시각 언어는 기존 paper/ink 토큰, Pretendard, 문장형 어법을 유지한다. 멤버 화면과 같은 브랜드, 다른 composition (ADR-0026/0045의 공유 셸 원칙 유지).

## 3. 정보 구조

1차 내비게이션을 4탭에서 **3탭**으로 줄인다. 데스크톱 top-nav와 모바일 tab-bar가 동일하다.

| 탭 | 흡수하는 기존 화면 | 내용 |
| --- | --- | --- |
| **오늘** | 대시보드, 운영 허브, 알림 발송 요약 | 날짜 헤드 + 다음 모임 히어로 + 처리할 일 큐 + 다가오는 일정 + 클럽 상태 |
| **모임** | 모임 목록, 기록 장부, 새 모임, 모임 편집, 마감, 피드백 문서 | 예정·과거 통합 수직 목록(구역 2개) → 회차 다이어리 상세 |
| **멤버** | 멤버, 초대 | 승인 대기 구역(조건부) + 명단 + 명명된 초대 링크 |

삭제되는 1급 화면: 운영 허브, 기록 장부(모임 목록에 흡수), 독립 초대 화면(멤버에 흡수). 알림 발송 작업대는 화면으로 유지하되 진입은 오늘 큐·다이어리의 발송 액션으로만 연결한다(1차 내비 없음).

## 4. 화면 설계

### 4.1 오늘 (홈)

- 헤드: `호스트 · 오늘` eyebrow + 날짜 h1 + "다음 모임까지 N일 · 처리할 일 N건" 문장 lede.
- **다음 모임 히어로**: 책 표지, 회차 pill, 상태 라벨, 참석/불참/미응답/발제 질문 숫자열(mono), 계산된 주 행동 1개(primary) + "모임 상세 열기"(quiet).
- **처리할 일 큐**: `구분 · 대상/사유 · 경과일 · 해결 CTA` 행. 주 버튼은 항상 해결 행위(승인 검토/출석 기록/게시)다. 항목은 명시적 해결·보류로만 큐를 떠나며, 처리 내역은 이력으로 남는다. 0건이면 구역이 사라지는 게 아니라 "오늘 처리할 일이 없습니다 · 마지막 확인 HH:MM" 한 줄을 남긴다(0은 데이터).
- 우측 레일: 다가오는 일정(수직), 클럽 상태 definition list, "운영 기록 전체 보기".
- 모임 당일에는 히어로가 **출석 카드로 승격**되고, 모바일에선 출석 명단이 홈 본문이 된다(§4.4).

### 4.2 모임 (목록 + 다이어리 상세)

- 목록: "다가오는 모임"과 "지난 모임" 두 구역의 단일 수직 목록. 행 = 회차 mono 번호, 제목, 날짜, 상태 라벨(단일 사전), attention 마커. 우상단 "새 모임 만들기". 휴지통(말소 기록)은 목록 하단의 조용한 링크 하나로 통일한다(현행 이중 진입 제거).
- 목록 행은 책 차례(목차) 문법으로 조판한다: 좌측 회차 mono 번호 + 제목, 점선 리더, 우측 정렬 mono 요약(예정 모임은 날짜, 지난 모임은 `참석 n/m` 등 원장 요약 — 항목은 조회 가능한 데이터로 한정). 아카이브가 부록이 아니라 클럽의 차례로 읽히게 하는 것이 목적이다.
- **다이어리 상세**: 상단 회차 페이저(`‹ No.27 · No.28 이번 모임 · No.29 만들기 ›`). 좌측 페이지 = 모임 정체(책, 일시, 장소, 발제, 범위, 공개 상태 + "멤버 시야로 보기") + **모임의 걸음** 세로 타임라인. 우측 페이지 = "지금 할 일" 카드(계산된 주 행동 1개) + 현재 단계에 필요한 것만(응답 현황 칩, 발제 질문, 호스트 메모, 변경 내역).
- 타임라인 단계: `모임 만들기 → 멤버와 준비 → 응답 모으는 중 → 모임 당일(출석) → 기록 정리 → 기록 게시`. 각 단계에 인라인 상태·액션이 붙어 마감·게시의 목적지 부재를 구조적으로 해소한다. lifecycle 계산 규칙은 ADR-0044의 표(단일 주 행동, readiness fail-closed)를 계승한다.
- **기록 정리 단계 = 장부 마감 체크리스트.** `출석 확정 → 소감 수집 → 기록 초안 → 피드백 문서 확인 → 멤버 게시` 5행이며, 완료 행에는 mono 타임스탬프가 봉인되어 이 페이지가 회차의 원장이 된다. 소감 리마인드는 미제출자에게만 보내고, 게시 후 도착한 소감은 자동 추가되어 게시가 소감 수집에 막히지 않는다. 종료 시 소감 요청 자동 발송은 서버 작업이 필요하므로 비범위(§8)로 분리하고, 이 스펙 범위에서는 체크리스트의 수동 발송 액션으로 시작한다.
- **자동 알림 가시성.** 호스트 이름으로 나가는 알림을 다이어리에서 `발송됨/예정` 상태와 날짜(mono)로 상시 노출하고 정책 토글로 끌 수 있게 한다(현행 계약: `sessionReminderEnabled` + `SESSION_REMINDER_DUE` 발송 이력). 호스트는 무엇을 보낼지 정하지만 멤버의 수신 채널 설정은 덮어쓰지 않는다. 다단(일주일 전·하루 전) 리마인드는 서버 작업이 필요하므로 비범위(§8)로 분리한다.
- **짧은 공지 인라인 컴포저.** 준비 단계 다이어리에 140자 인라인 컴포저를 두고 수신자를 상태로 고른다(전원/참석/미응답 — 기본값 미응답). 참석 확정 멤버에게 재촉 알림을 보내지 않는 것을 기본 규칙으로 한다. 장문·예약·수신자 세분화는 알림 작업대로 연결한다.
- 편집·마감·피드백 문서는 다이어리의 패널/시트로 유지(현행 라우트 계약 유지 가능). `/closing` 등 리다이렉트 경로는 다이어리의 해당 단계 앵커로 착지시킨다.

### 4.3 멤버

- 헤드 lede: "활동 12명 · 둘러보기 2명 · 쉬는 중 1명" 문장 요약.
- **가입 승인 대기 구역**: 대기자가 있을 때만 렌더링(Luma 패턴). 신청 경로(초대 링크 이름), 신청 메모, 승인/거절. 승인·거절은 통보를 포함한 결정임을 구역 헤더에 명시한다.
- 명단 테이블: 이름, 상태 badge, 함께한 기간·참석 누계·**알린 불참**·**무단 불참**·마지막 참석(모두 mono·tabular, 우측 정렬), **들어온 경로**(초대 링크 이름과 연결). 응답(RSVP) 축과 출석 사실 축을 분리해 집계하며, "N회 연속 불참"은 호스트 전용 신호이고 자동 조치가 없음을 각주로 밝힌다. 멤버별 누계가 현행 host API로 조회되지 않으면 해당 열은 서버 계약 확장(별도 스펙) 이후로 미루고, 이 스펙 범위에서는 조회 가능한 열만 먼저 넣는다(§9의 5단계 전에 확인).
- **초대 링크**: 같은 화면의 하단 구역. 링크마다 호스트 전용 이름, 마스킹된 URL(+명시적 "전체 보기·복사"), 활성/만료/소진/중지 4상태, 사용 n/최대 n(mono). 중지는 즉시 적용 + 이력 보존.
- 멤버 제거는 오버플로 메뉴로 격리하고, 확인 화면에서 기록 처리 정책(개인정보 익명화, 참석 사실 보존)을 행동 전에 보여준다.

### 4.4 모바일

- 하단 3탭(오늘/모임/멤버) + safe-area. 상단 헤더는 kicker(`호스트 · 오늘`) + 제목.
- 모임 당일 홈: D-day 카드 + 원탭 출석 명단(행 전체가 44px+ 타겟, 탭 = 즉시 커밋, 저장 버튼 없음), "나머지 N명 모두 참석으로 표시" 일괄 기본값, 하단 탭바 위 지속 Undo 스트립.
- 다이어리 모바일: 세로 타임라인이 본문 전체. 현재 단계 카드에 인라인 CTA, 하단 sticky 주 행동 1개(본문 CTA와 중복 announce 금지 — 현행 규칙 유지).
- 표는 모바일에서 `핵심 사실 1줄 + 상태 + 시각` 리스트로 재구성한다(가로 스크롤 표 금지).

## 5. 용어·상태 사전 (개념 1개 = 라벨 1개)

| 개념 | 단일 라벨 | 금지 표현 |
| --- | --- | --- |
| 세션 객체 | 모임 (URL은 `sessions` 유지) | 세션, 모임 문서, 장부(객체 지칭) |
| DRAFT | 작성 중 | 예정, 모임 작성 중 |
| OPEN | 준비 중 | 진행 중, 멤버와 준비 중(상태 라벨로는) |
| CLOSED | 기록 정리 중 | 종료 |
| PUBLISHED | 게시됨 | 공개됨, 공개 완료 |
| 소프트 삭제 | 말소 (복구 가능 기간 명시) | 삭제/제거 혼용 |
| 초대 중단 | 중지 (이력 보존) | 취소, 폐기 |
| 사전 통보 불참 | 알린 불참 | 결석·노쇼 혼용 |
| 통보 없는 불참 | 무단 불참 | 결석·노쇼 혼용 |

숫자 정의: "참석 n/m"의 분모는 항상 **응답 요청 대상 멤버 수**로 고정하고, 원장성 화면에는 기준 시각(as-of)을 표기한다.

## 6. 상태·복구 문법 (전 화면 공통)

`front/DESIGN.md`의 state grammar(loading/empty/stale/partial/forbidden/conflict/unknown-outcome/unavailable)를 계승하되, 다음을 전 화면 계약으로 승격한다:

- 빈 상태 4분화: 최초 사용 / 필터 결과 없음 / 오류 / 권한 없음을 다른 문안으로. 텍스트 전용, 일러스트 없음.
- 파괴 행위: 즉시 실행 + Undo(8초+) + 말소 목록이 기본. 확인 다이얼로그는 비가역 행위(멤버 제거 등)에만, 영향 미리보기 포함.
- 완료 근거는 toast가 아니라 큐 이탈 + 이력 기입. 발송 실패·부분 실패는 처리할 일 큐에 잔존한다.
- 필드 가시성 라벨: 공개/멤버/호스트 전용을 편집 지점에 표기하고 "멤버 시야로 보기"를 다이어리에서 제공한다.

## 7. 페이지 셸 규율

페이지 타입을 3종으로 고정한다: **오늘형**(트리아지), **목록형**(모임 목록·멤버), **다이어리형**(모임 상세). 공유 PageHeader(eyebrow + h1 + 문장 lede + 우측 primary 1개)와 hairline 섹션 타이틀을 모든 화면이 사용한다. 새 페이지 패턴 추가는 두 곳 이상 재사용이 확인될 때만 허용한다(Ghost rule-of-two).

## 8. 비범위 (Non-goals)

- 서버 API·schema·auth 계약 변경 없음 (ADR-0038 cursor epoch, ADR-0023/0028 mutation 계약 유지).
- 플랫폼 어드민(`/admin/**`) Editorial Operations Ledger는 그대로 둔다 (ADR-0045의 admin 범위 유지).
- 멤버/게스트/퍼블릭 화면 composition 변경 없음.
- 알림 워크벤치 내부 리디자인은 후속 작업 (진입 경로만 재배치).
- 다이제스트 알림(모임 전날/다음날 요약), 다단 리마인드(일주일 전·하루 전), 종료 시 소감 요청 자동 발송, 멤버별 참석·불참 누계 API는 서버 작업이 필요하므로 별도 스펙으로 분리.

## 9. 단계적 구현 제안

1. **용어·상태 사전 통일** — 라벨 상수 단일화, 화면 변경 없음. 저위험 선행.
2. **오늘(홈) 트리아지** — 대시보드 재구성 + 처리할 일 큐 데이터 통합(운영 허브 신호 흡수).
3. **모임 목록 통합** — 기록 장부 흡수, 휴지통 단일 진입.
4. **다이어리 상세** — Focus Deck을 타임라인 스프레드로 재조립(패널·계약 재사용).
5. **멤버+초대 통합** — 승인 대기 구역, 명명된 초대 링크.
6. **내비 3탭 전환 + 구 라우트 리다이렉트** — 마지막에 스위치.

각 단계는 독립 릴리스 가능하며, 단계별 검증은 `pnpm --dir front lint/test/build` + 영향 라우트 e2e, 시각 계약은 CT 스크린샷 재잠금(320/390/768/900/1024/1440)으로 한다.

## 10. 검증 계획

- 코드 변경 단계마다: frontend lint/test/build, 영향 라우트 e2e (`pnpm --dir front test:e2e`).
- 시각 권위: `front/DESIGN.md` 갱신 + tracked CT 스크린샷 재잠금. reduced-motion, 44px 타겟, 한국어 줄바꿈, 200% zoom proxy는 기존 automated helper 계승.
- 완료 기준(모바일): "한 손으로, 10초 안에, 대화를 끊지 않고 오늘 출석을 마칠 수 있는가"를 실기기에서 확인.
- ADR-0046 `Proposed → Accepted` 승격은 6단계 완료 + 스크린샷·e2e 정합 + `front/DESIGN.md`/architecture 문서 동기화 후에만 한다. 그 시점에 ADR-0044를 `Superseded by ADR-0046`으로, ADR-0045를 admin 범위로 축소 표기한다.

## 11. 시안

방향 검증용 정적 목업 6종(A/B/C 3방향 × 데스크톱·모바일)을 세션 중 제작해 검토했고, A+B 조합이 승인되었다. 이후 병행 세션에서 원장 행 문법 검증용 목업 6종(트리아지 홈, 모임 상세 준비 단계, 장부 마감, 멤버 원장, 차례식 홈 변형, 모바일 홈·당일 출석)을 추가 제작해 승인받았고, 이 문서의 §4.2 차례식 목록·장부 마감·자동 알림 가시성·인라인 컴포저와 §4.3 출석 이력 열이 그 결과다. 승인된 2차 목업(HTML 원본 + 스크린샷)은 `docs/development/host-redesign-mockups/`에 비규범 참고 자료로 보존한다. 시안과 이 문서가 다르면 이 문서의 화면 설계 서술이 기준이며, 구현 후 시각 권위는 tracked CT 스크린샷으로 넘어간다.
