# ReadMates 플랫폼 어드민 재설계 — 케이스 데스크 + 운영 서사

- 날짜: 2026-08-27
- 표면: Platform admin (`/admin/**`)
- 상태: 설계 방향 승인됨 (A안 케이스 데스크 + B안 운영 서사 조합)
- ADR impact: **supersede/update** — ADR-0045의 admin composition을 대체, ADR-0039의 운영 문법은 계승하되 내비 축과 화면 셸을 재정의. 신규 `Proposed` ADR-0046.
- 관련: `front/DESIGN.md` §Editorial Operations Ledger, ADR-0039, ADR-0040, ADR-0045, `front/features/platform-admin/**`

## 1. 문제

어드민 10개 라우트 중 Editorial Operations Ledger 문법(signal → case → docket → command → receipt)을 실제 구현한 화면은 Today뿐이다. 코드·스크린샷 기준 진단:

- **핸드롤 섬.** Support·Audit·Analytics·클럽 상세는 `AdminPageContext`/`AdminSafeActionDock`/`AdminStatePanel` 등 공유 프리미티브를 거의 쓰지 않고 자체 헤더·폼·영수증을 만든다. AI Ops는 route H1과 PageContext H1이 이중으로 뜬다.
- **멤버 화면과 톤 단절.** `Club registry`·`S5 Operations` 영문 eyebrow, `ACTIVE`/`PRIVATE`/`ASSIGNED` enum 원문 노출, "지원 grant ledger" 한/영 혼용 — paper/ink 문장형 정체성 밖에 있다.
- **용어 3중 분열.** 오늘/오늘 할 일/운영 케이스, AI Ops/AI 운영/AI 작업, 영수증/명령 기록/명령 접수 완료가 같은 개념을 다르게 부른다.
- **하루 루프 단절.** Today에서 잡은 알림 실패 케이스가 Notifications의 클러스터·전역 replay로 문법이 이어지지 않고, 클럽 상세·Support·Audit에서는 Today에서 학습한 패턴이 전이되지 않는다.
- **상태·빈 상태 처리 분기.** StatePanel 계열과 plain `<p role="alert">` 계열이 화면별로 갈린다.

리서치 근거(요약): Linear Triage("큐는 정규 뷰에서 제외된 인박스, 무시엔 사유 필수"), Stripe Radar(도켓 내 이전/다음 순회), Stripe Event deliveries(다음 재시도 시각 표기, "수동 재발송은 자동 재시도를 취소하지 않는다"), Sentry(조건부 스누즈, 상태·이력 단일 트랜잭션), ISA-101(정상은 조용히·숫자 숨김, 알람 요약 바 상주, 색은 이탈에만), Ghost Shade(페이지 패턴 제한, 역할 기반 명명), Primer(폭발 반경 비례 마찰).

## 2. 결정된 방향 — A(케이스 데스크) + B(운영 서사)

- **케이스 데스크가 기본 작업 문법.** 오늘 화면 = 좌측 케이스 큐 + 우측 증거 도켓, 도켓 안에서 이전/다음 순회. ADR-0039/0045의 signal→case→docket→command→receipt 문법을 유지하되, 이번에는 **모든 명령·검토 화면이 같은 문법을 쓴다.**
- **서사가 기본 관측 문법.** 홈 진입과 서비스 건강은 한 문장 서사 + 상주 알람 요약 바. 정상 항목은 숫자를 펼치지 않고, 이탈만 위로 올라온다. KPI 카드 벽 금지.
- 시각 언어는 멤버/호스트와 같은 paper/ink 토큰, Pretendard, 문장형 한국어. 표 숫자는 `tnum`(기존 `.ledger-number` 계승).

## 3. 정보 구조

사이드 내비를 4그룹에서 다음으로 재편한다. 라벨은 전부 한국어로 통일한다.

| 내비 | 흡수하는 현행 라우트 | 내용 |
| --- | --- | --- |
| **오늘** | today | 케이스 데스크 (큐 + 도켓) + 상단 서사·알람 바 |
| **클럽** | clubs, clubs/:id | 클럽 장부(목록) → 클럽 상세(공유 셸로 재조립) |
| **파이프라인** | notifications, ai-ops, health | 배달 원장, 작업 원장(AI), 서비스 건강(서사형) |
| **원장** | audit, support, analytics | 운영 기입(감사), 접근 원장(지원), 분석 부록 |
| (내비 밖 상주) | public-takedown | 긴급 공개 회수 — 사이드 하단 고정 링크, 비상 레인으로 분리 유지 |

브레드크럼·내비·페이지 제목의 용어를 단일 사전으로 고정한다 (§6).

## 4. 화면 설계

### 4.1 오늘 — 케이스 데스크

- 최상단 **알람 요약 바** (모든 어드민 화면 공통 상주): "주의 N건 — 요약 · 미확인 신호 · 서비스 상태 · as-of 시각". 0건이면 무채색 한 줄.
- 좌측 큐: 케이스 행 = 대상·판정 요약·분류·경과(mono). 보류 항목은 기본 숨김(토글로 표시). 처리한 케이스는 큐에서 사라지고 운영 기입에서 열람.
- 우측 도켓, 고정 순서: ① **판정 문장**(가장 큰 타입) ② 발화한 신호(임계 vs 실측) ③ 증거(집계→클러스터→원문 3단 줌) ④ 명령(이 케이스에서 가능한 것만) ⑤ **이 대상의 최근 기입**(감사 원장 프리필터 인라인).
- 도켓 헤더에 **이전/다음 + "n / m"** 순회. 처리 후 자동으로 다음 케이스.
- 큐 이탈 4경로: **처리 / 보류 / 무시(사유 필수) / 병합**. 보류는 시각 OR 조건(신호 재발 시 자동 복귀, 복귀 시 "보류했으나 악화되어 돌아옴" 라벨).
- 케이스는 클럽·배달·작업 목록의 기본 뷰에 나타나지 않는다(큐는 정규 목록에서 제외된 인박스).

### 4.2 홈 진입·서비스 건강 — 운영 서사

- 서비스 건강 페이지 구조: ① 한 문장 서사("모든 클럽 정상. 마지막 이상은 …") ② 이탈이 있을 때만 해당 항목이 숫자와 함께 펼쳐짐 ③ **최근에 바뀐 것** 타임라인(배포·설정 변경·작업 실패를 한 줄기로) ④ 색인 그리드(각 항목은 전용 화면 진입점, 목적지 아님).
- 정상 항목은 숫자를 렌더링하지 않는다. 색은 이탈에만; 정상은 무채색.
- 차트를 쓰는 경우 모노크롬 스파크라인 + 정직한 Y축만 허용.

### 4.3 파이프라인 — 배달 원장·작업 원장

- 배달 원장 행 = `발송됨/대기/실패` 3상태 + **다음 재시도 예정 시각** + 시도 배지("2차 시도"). 그룹 키는 `클럽+알림 유형+오류 클래스`(상태로 그룹핑 금지).
- 상세 = 시도별 타임라인(시각·결과·오류), 멱등키 노출(중복 발송 자가 확인).
- 재발송 UI에 고정 경고: **"수동 재발송은 자동 재시도를 취소하지 않습니다."** 재발송은 개별·클러스터·일괄 3층.
- 작업 원장(AI): run/attempt 분리, 대기 시간과 실행 시간 구분 표시, 멈춤 감지("N분째 진행 없음"). AI 제안은 전용 모듈에만 살고 사람이 설정한 값과 시각적으로 섞지 않는다. AI 경로 장애가 트리아지를 막지 않는다.

### 4.4 클럽

- 목록: 한국어 eyebrow·라벨, enum 원문 노출 금지("활동/비공개/연결됨" 사전 라벨). 정상 행은 무채색, 신호 있는 행만 상태 표기.
- 상세: 핸드롤 폼 스택을 공유 셸로 재조립 — PageHeader + 사실 dl + 명령은 SafeActionDock, 영수증은 ReceiptTimeline. 하단에 "이 클럽의 최근 기입" 프리필터 원장.
- 클럽 스코프는 Vercel식 필터로: 배달/작업/기입 화면이 클럽 상세와 별개 페이지가 아니라 같은 화면의 스코프 전환.

### 4.5 원장 — 운영 기입·접근·분석

- **운영 기입(감사)**: 한 행 = 한 문장(`시각 · 행위자가 대상에 무엇을 함 · 사유 · 결과`). 결과 값은 성공/실패/**차단**/진행 4종. 사유가 없으면 "사유 없음"을 명시 렌더. 내부 이벤트명·원시 필드는 드로어에만. 3분할(필터/원장/드로어)로 Today와 같은 문법. 모든 엔티티 화면에서 프리필터 진입.
- **접근 원장(지원)**: 발급 검토를 SafeActionDock 문법으로 재조립. 사유·만료는 필수 필드, 발급·만료·취소가 각각 기입으로 남고 활성 세션은 알람 바에 상주 표기.
- **분석 부록**: 결정을 바꾸는 숫자만. CSV 내보내기는 `EXPORT_ANALYTICS` 게이트 유지.

### 4.6 긴급 공개 회수

- 현행 L3 문법(preview → command → receipt → convergence) 유지. `공개 → 내림(복구 가능) → 파기(영구)` 2단계 묘비를 명시하고 공개→파기 직행 경로를 만들지 않는다. 파기 예정 목록을 "말소·회수 기록" 장에 노출.

### 4.7 모바일 — 온콜 표면

- 640px 이하에서 큐와 도켓은 별도 화면(목록→상세)으로 분리(현행 Today 계약 유지).
- 가능한 동작은 확인/보류/재발송/해소 메모뿐. **파괴·회수 명령은 모바일에서 제공하지 않는다.** 해소 메모 필드는 모바일에도 있고 원장에 기입된다.
- 선택 모드 일괄 처리(같은 클러스터의 실패 N건).

## 5. 명령 마찰 3등급 (ADR-0040 safe-command 위에 UI 규약)

| 등급 | 기준 | 마찰 |
| --- | --- | --- |
| L1 되돌릴 수 있음 | 원복 1클릭 | 확인 없음 + 실행 취소 + 기입 |
| L2 단일 대상·외부 가시 | 되돌릴 수 있으나 외부 노출 | 손실 인벤토리 다이얼로그 + 사유 + 영수증 |
| L3 영구·광역 | 비가역 또는 클럽 전체 | dry-run 프리뷰 → 대상명 타이핑 → 영수증+수렴 |

- 확인 버튼 라벨은 행위 그 자체("소진된 8건 재발송"). "확인/OK" 금지.
- dry-run과 차단된 시도도 기입에 남는다.
- 판단과 집행 분리: 승인이 곧 실행인 명령은 L1에만 허용.

## 6. 용어 사전 (개념 1개 = 라벨 1개)

| 개념 | 단일 라벨 | 금지 표현 |
| --- | --- | --- |
| 트리아지 단위 | 케이스 | 사건, 운영 케이스(제목 외 수식) |
| 내비 '오늘' | 오늘 | 오늘 할 일 |
| AI 표면 | 작업 원장 / AI 작업 | AI Ops, AI 운영 |
| 알림 표면 | 배달 원장 | 알림/Outbox 운영, Failure clusters |
| 감사 표면 | 운영 기입 | 감사 로그, audit ledger |
| 명령 완료 증빙 | 영수증 | 명령 기록, 명령 접수 완료, 처리 완료 |
| 지원 발급 이력 | 접근 원장 | 지원 grant ledger, 이력 |
| 결과 값 | 성공 / 실패 / 차단 / 진행 | 영문 enum 원문 |

영문 eyebrow·내부 enum·내부 이벤트명은 화면 1급 텍스트로 노출하지 않는다. 시각은 절대 시각(+타임존 기준) 우선, 상대 시각은 보조.

## 7. 페이지 셸 규율

페이지 타입 3종으로 고정: **데스크형**(오늘 — 큐+도켓), **원장형**(클럽 목록·배달·작업·운영 기입·접근 — 필터/표/드로어), **서사형**(건강·홈 진입 — 서사+색인). 긴급 회수는 기존 단계형 폼 유지(예외 1건, 문서화된 예외). 모든 화면이 `AdminPageContext` 계열 공유 헤더와 알람 바를 사용하고, 새 패턴은 두 곳 이상 재사용 확인 후에만 추가한다. 컴포넌트 명명은 역할 기반(`PageHeader`)으로, 화면 지칭(`ClubDetailHero`) 금지.

## 8. 비범위 (Non-goals)

- 서버 capability·safe-command 계약(ADR-0040), exact capability 모델 변경 없음.
- 호스트/멤버/게스트/퍼블릭 화면 변경 없음 (호스트 재설계는 별도 보류 브랜치의 스펙).
- 알림 파이프라인 서버 동작(재시도 정책 등) 변경 없음 — UI 표현만.
- 조건부 스누즈(신호 재발 시 자동 복귀)의 서버 판정이 없다면 1단계에서는 시각 기반 보류만 구현하고 조건 복귀는 후속으로 분리.

## 9. 단계적 구현 제안

1. **용어 사전 통일 + 영문 eyebrow/enum 제거** — 라벨 상수화, 저위험 선행.
2. **알람 요약 바 + 서사형 건강 페이지** — 관측 축 교체.
3. **오늘 케이스 데스크 보강** — 도켓 고정 순서, 이전/다음 순회, 무시 사유 필수, 대상 최근 기입 인라인.
4. **원장형 셸 통일** — 운영 기입(감사)·접근(지원)·분석을 공유 프리미티브로 재조립.
5. **파이프라인 재편** — 배달 원장(다음 재시도·시도 배지·경고 문구), 작업 원장.
6. **클럽 상세 재조립 + 내비 재편** — 마지막에 스위치, 구 경로 리다이렉트.

각 단계는 독립 릴리스 가능. 검증은 frontend lint/test/build + admin e2e, CT 스크린샷 재잠금(320/390/768/900/1024/1440).

## 10. 검증 계획

- 단계별 `pnpm --dir front lint/test/build`, 영향 라우트 `pnpm --dir front test:e2e`.
- `front/DESIGN.md` §Editorial Operations Ledger 갱신 + tracked CT 스크린샷 재잠금.
- ADR-0046 `Proposed → Accepted` 승격은 6단계 완료 + 시각 계약·e2e 정합 + 문서 동기화 후. 그 시점에 ADR-0045를 host·admin 모두 superseded로 정리(호스트 안 진행 여부와 함께 판단)하고 ADR-0039의 내비 축 서술을 갱신한다.
