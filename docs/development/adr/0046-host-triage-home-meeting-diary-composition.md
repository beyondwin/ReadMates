# ADR-0046: 호스트 워크스페이스를 오늘 트리아지 + 모임 다이어리로 재구성

- 상태: Accepted
- 결정일: 2026-08-27
- 작성자: design/front
- 관련: ADR-0044, ADR-0045, ADR-0026, ADR-0038, `docs/development/2026-08-27-readmates-host-triage-diary-redesign-design.md`, `front/DESIGN.md`

> Stage 6 게이트에서 코드·테스트·`front/DESIGN.md`·`docs/development/architecture.md`가 일치해 `Accepted`로 승격했다.

## 컨텍스트

호스트 앱은 라우트 12개에 홈 성격 화면이 4개(오늘, 운영 허브, 모임 목록, 기록 장부)이고, 같은 lifecycle을 화면마다 다른 라벨로 말한다(DRAFT = 작성 중/예정/모임 작성 중). 확인 필요 항목은 세 화면에 분산되고, 운영 허브·초대·알림은 1차 내비게이션에 없다. `/closing`은 Focus Deck으로 리다이렉트되어 모임 직후 마감 목적지가 없다. ADR-0044/0045가 고정한 Focus Deck 구성은 "현재 모임의 단일 주 행동"은 해결했지만, 화면 간 역할 중복과 어휘 분열은 남겼다. 2025-2026 운영 도구 벤치마크(Airbnb Today, Luma Pending/승인 플로우, Ghost 페이지 타입 3종, Linear 큐 문법)와 블라인드스팟 감사를 반영해 재구성이 승인되었다.

## 결정

호스트 1차 내비게이션을 3탭(오늘·모임·멤버)으로 고정하고, 홈은 "처리할 일 단일 큐 + 다음 모임 히어로"의 트리아지 화면으로, 모임 상세는 생성→준비→당일→기록→게시를 한 세로 타임라인으로 담는 다이어리 스프레드로 구성한다. 기록 장부는 모임 목록에, 초대는 멤버 화면에, 운영 허브는 오늘 큐에 흡수한다. 상태·동사 라벨은 개념당 하나의 사전으로 고정한다.

## 근거

- 홈의 성공 기준을 "지표를 보여줬는가"가 아니라 "다음 행동이 정해졌는가"로 잡는다(Airbnb Today 패턴). 큐 행의 주 버튼은 해결 행위이고, 항목은 명시적 해결로만 큐를 떠난다.
- 대기 상태는 배지 산개가 아니라 "있을 때만 존재하는 구역"으로 표현한다(Luma Pending). 조용한 에디토리얼 정체성과 정합한다.
- 마감·게시를 다이어리 타임라인의 단계로 두면 `/closing` 목적지 부재가 구조적으로 해소되고, ADR-0044의 단일 주 행동 계산 규칙은 타임라인의 현재 단계 카드로 계승된다.
- 페이지 타입을 3종(오늘형/목록형/다이어리형)으로 제한하고 공유 PageHeader를 강제해 셸 재구현 드리프트를 차단한다(Ghost rule-of-two).

## 대안

| 대안 | 기각 이유 |
|------|----------|
| 현행 Focus Deck 유지 + 카피만 통일 | 홈 4중복과 유령 화면(운영 허브·초대·알림) 문제가 남는다. |
| C안: 단일 장부(목차 레일 + 원장 지면) | 감사성·데스크톱 밀도는 최강이나 모바일 현장 운영(원탭 출석)이 약하고, 멤버 화면과 셸 이질감이 커진다. |
| B안 단독(모임이 유일한 1급 객체) | 모임 밖 운영 신호(가입 승인, 초대 소진)가 다시 배지로 흩어진다. |

## 결과

긍정적:
- 호스트 학습 비용 감소: "지금 뭘 해야 하나"는 오늘, "이번 모임은 어디까지 왔나"는 다이어리로 질문-화면이 1:1.
- 확인 필요의 단일 소스 큐 + 처리 이력으로 운영 원장 정체성 강화.
- 1급 화면 수 감소(11→6 내외)로 시각 계약·스크린샷 잠금 표면 축소.

부정적/감수한 비용:
- 라우트 재배치와 구 경로 리다이렉트, CT 스크린샷 전면 재잠금 비용.
- ADR-0044/0045(2026-08-26 Accepted)를 하루 만에 뒤집는 결정 이력이 남는다 — 시안 검증을 먼저 거쳤음을 스펙에 기록해 완화.
- 알림 워크벤치가 내비 밖으로 이동해 진입 클릭이 1회 늘 수 있다(오늘 큐가 보상).

## 검증

- 스펙 §9의 6단계 각각에서 frontend lint/test/build + 영향 라우트 e2e.
- 시각 계약: `front/DESIGN.md` 갱신과 tracked CT 스크린샷 재잠금(320/390/768/900/1024/1440).
- 모바일 완료 기준: 한 손, 10초, 대화 중단 없이 당일 출석 완료.
- `Accepted` 승격 시 ADR-0044를 `Superseded by ADR-0046`으로, ADR-0045를 admin 범위로 축소 표기하고 인덱스를 갱신한다.

## 후속 작업

- 모임 전날/다음날 다이제스트 알림(서버 작업) — 별도 스펙/ADR 후보.
- 멤버별 참석·알린 불참·무단 불참 누계 조회의 서버 계약(멤버 원장 열 데이터) — 현행 host API로 부족하면 별도 스펙 후보.
- 멤버 제거 시 기록 익명화-보존 정책의 서버 계약 명문화 — 별도 ADR 후보.
- 알림 워크벤치 내부 리디자인.
- 마감 체크리스트 완료 시각(기록 초안·피드백 문서 확인·멤버 게시, 그리고 소감 수집 알림의 실제 소감 이벤트) — 현행 closing-status 계약에 timestamp가 없어 봉인 스탬프 칸을 비운다. 서버 후보.
- 스펙 §4.2 `짧은 공지 인라인 컴포저`(140자, 상태별 수신)는 confirm 계약에 body 필드가 없어 구현하지 않았다. 서버가 body를 받으면 재검토.
