# ReadMates v2.2.0 Release and Production Deployment Plan

> **For agentic workers:** Execute inline in order. Do not dispatch live AI provider calls, email sends, or private-data mutations as smoke evidence.

**Goal:** Publish the accumulated `v2.1.0..HEAD` product changes as `v2.2.0`, synchronize active documentation, and deploy the same immutable tag to OCI backend and Cloudflare Pages production.

**Architecture:** Use a release PR because the scope includes Flyway migrations, API/auth behavior, and deployment workflow changes. Promote a scanned ARM64 server digest first, apply V43–V46 through Spring startup Flyway, verify backend health, then deploy the same tag's frontend and Pages Functions.

**Tech Stack:** Git/GitHub Actions, Kotlin/Spring Boot 4, MySQL/Flyway, React/Vite, pnpm 11.13.1 via Corepack, GHCR/Trivy, OCI Docker Compose, Cloudflare Pages.

## Global Constraints

- Preserve public-repo safety: no secrets, private hosts, member data, OCIDs, or token-shaped examples in tracked files or release notes.
- Never move an existing tag or force-push. A failure after tag publication is fixed with a new patch tag.
- Keep backend-first ordering and do not dispatch frontend production before GHCR scan, OCI Flyway, and backend health succeed.
- Do not execute billable AI calls, real email sends, or member-data mutations as release smoke.
