# ReadMates 내 공간 참여 여정 리디자인

작성일: 2026-07-28
상태: 디자인 승인 완료, 작성본 검토 대기

## 1. 요약

`/clubs/:clubSlug/app/me`의 `최근 책별 기록`을 제거하고, 사용자가 자신의 참여가 꾸준히 쌓였음을 확인하는 `참여 여정`으로 대체한다.

현재 멤버 홈은 RSVP, 읽기 진행률, 질문처럼 지금 해야 할 행동을 안내한다. 아카이브와 `/app/me/records`는 과거 기록 탐색을 담당한다. 내 공간에서 최근 책 세 권을 다시 보여주면 두 화면과 역할이 겹친다.

내 공간은 다음 질문에 답하는 개인 회고 화면이 된다.

1. 지금까지 몇 번 함께했는가?
2. 최근 참여 흐름은 어떠한가?
3. 완독, 질문, 서평이 얼마나 쌓였는가?
4. 다음 모임으로 이 흐름을 이어갈 수 있는가?

비교 기준은 클럽 평균이나 다른 멤버가 아니라 과거의 나다. 경쟁, 순위, 배지 대신 조용한 문장과 회차 흐름으로 성취를 표현한다.

## 2. 목표

1. 사용자가 10초 안에 전체 참여 규모와 최근 참여 흐름을 이해하게 한다.
2. 최근 기록 목록을 아카이브 및 내 기록 전체 화면과 중복 렌더링하지 않는다.
3. 참여의 꾸준함을 중심에 두고 완독, 질문, 서평을 보조 성취로 보여준다.
4. 중간 합류, 참여 대상 제외, 출석 미확정을 불참으로 잘못 계산하지 않는다.
5. 열린 세션과 쓰기 권한이 있을 때만 부드러운 다음 참여 행동을 제공한다.
6. 로그아웃을 내 공간에서 찾을 수 있게 하되 독서 성취보다 높은 위계를 갖지 않게 한다.
7. 데스크톱과 모바일에서 같은 의미 순서, 접근 가능한 상태 표현, 실용적인 조작 영역을 유지한다.

## 3. 비목표

- 멤버 홈의 `다음 할 일`, 읽기 페이스 또는 현재 세션 준비 보드 재설계
- `/app/archive`, `/app/me/records` 또는 회차 상세의 전면 리디자인
- 다른 멤버, 클럽 평균 또는 순위를 사용한 비교
- 점수, 레벨, 배지, 보상 또는 출석 경쟁 기능
- 새로운 기록 작성 기능
- 계정 설정, 알림 설정, 탈퇴 정책 변경
- 새 데이터베이스 테이블 또는 Flyway migration
- 공개 사이트, 호스트 앱 또는 플랫폼 관리자 화면 변경

## 4. 검토한 접근

### 4.1 선택: 참여 여정형

전체 누적 성취와 최근 참여 대상 회차의 흐름을 한 지면에서 보여준다.

장점:

- 홈의 현재 행동 및 아카이브의 상세 기록과 역할이 겹치지 않는다.
- 참여 독려와 개인 회고를 함께 제공할 수 있다.
- 기존 프로필 및 개인 여정 데이터를 대부분 재사용할 수 있다.
- ReadMates의 차분한 개인 독서 책상 정체성과 맞는다.

### 4.2 제외: 개인 리포트형

참여율, 완독률, 질문 변화 등을 차트와 퍼센트로 보여주는 방식이다.

제외 이유:

- 일반적인 SaaS 대시보드처럼 보이기 쉽다.
- 이력이 적은 멤버에게 퍼센트가 과장되거나 빈약하게 보일 수 있다.
- 정확한 숫자보다 참여가 쌓이는 감각을 우선한다는 목표와 맞지 않는다.

### 4.3 제외: 성취 배지형

`3회 연속 참여`, `첫 완독`, `질문 10개` 같은 배지를 수집하는 방식이다.

제외 이유:

- 경쟁과 게임화가 제품의 조용한 기록장 분위기를 약화한다.
- 배지 규칙, 버전, 회수 정책 및 별도 상태 관리가 필요하다.
- 현재 목표보다 범위가 크다.

## 5. 정보 구조

내 공간의 기본 순서는 데스크톱과 모바일에서 동일하다.

```text
내 공간
└─ 나의 서재
   ├─ 전체 기록
   │  ├─ 함께한 모임 N회
   │  └─ 함께한 기간
   ├─ 최근 참여 흐름
   │  ├─ 최근 확인된 N회 중 M회 참여
   │  ├─ 조건을 만족할 때 현재 연속 참여
   │  ├─ 회차별 참석 상태
   │  └─ 참석 회차의 읽기 진행 또는 완독
   ├─ 다음 참여 안내
   │  └─ 조건을 만족할 때 이번 세션 보기
   ├─ 보조 독서 성취
   │  ├─ 완독 N/M
   │  ├─ 질문 N
   │  └─ 서평 N
   ├─ 내 책별 기록 전체 보기
   └─ 계정
      └─ 로그아웃
```

`최근 책별 기록` 목록은 내 공간에서 제거한다. 책, 표지, 회차 상세 및 피드백 문서 진입은 `/app/me/records`가 계속 담당한다.

## 6. 참여 통계 정의

### 6.1 전체 성취

- `함께한 모임`: 현재 클럽과 현재 membership 범위에서 참석이 확정된 archive-visible 회차 수
- `함께한 기간`: 현재 membership의 `joinedAt`부터 현재 월까지의 개월 차이
- `완독`: 참석이 확정된 회차 중 읽기 진행률이 100 이상인 회차 수
- `질문`: 현재 membership이 남긴 전체 질문 수
- `서평`: 현재 membership이 남긴 전체 장문 서평 수

가입 기간은 다음 규칙으로 표현한다.

- 같은 달: `이번 달부터 함께`
- 12개월 미만: `함께한 지 N개월`
- 12개월 이상: `함께한 지 N년 M개월`
- `joinedAt`이 유효한 `YYYY-MM`이 아니거나 현재 월보다 미래면 기간 문구를 렌더링하지 않는다.

전체 성취에는 다른 클럽, 이전 membership, 다른 멤버의 활동을 포함하지 않는다.

### 6.2 최근 참여 대상 회차

최근 흐름은 클럽의 최근 회차 6개가 아니라 현재 membership이 실제 참여 대상이었던 최근 공개 회차 최대 6개다.

참여 대상 회차는 다음 조건을 모두 만족한다.

- 현재 클럽의 `PUBLISHED` 회차
- 현재 membership의 `session_participants` 행이 존재
- 해당 행의 `participation_status`가 `ACTIVE`

따라서 다음 회차는 타임라인, 분모 및 연속 참여 계산에서 제외한다.

- membership 가입 전 회차
- 해당 멤버가 참여 대상으로 추가되지 않은 회차
- 해당 회차의 참여 대상에서 제거된 회차
- 다른 클럽 또는 다른 membership의 회차

최근 참여 대상이 2회라면 `최근 2회 중 2회 함께했어요`처럼 실제 대상 수를 사용한다. 여섯 칸을 채우기 위해 가입 전 회차를 불참으로 만들지 않는다.

### 6.3 출석 상태

출석은 다음 세 상태를 보존한다.

- `ATTENDED`: 참여
- `ABSENT`: 불참
- `UNKNOWN`: 출석 미확인

기존 `attended: Boolean`만으로는 참여 정보가 없는 상태, 실제 불참, 출석 미확정을 구분할 수 없다. `/api/app/me`의 `recentAttendances` item에 `attendanceStatus`를 추가하고 프런트 참여 여정은 새 필드를 기준으로 계산한다.

```json
{
  "sessionNumber": 8,
  "attended": false,
  "attendanceStatus": "UNKNOWN",
  "readingProgress": 0
}
```

기존 `attended` 필드는 이 변경에서 제거하지 않는다. `attendanceStatus == "ATTENDED"`일 때만 `true`이고 `ABSENT` 또는 `UNKNOWN`이면 `false`다. 기존 소비자의 호환성을 위한 필드이며 새 참여 여정 계산에는 사용하지 않는다.

서버 query는 최근 클럽 회차를 `left join`한 뒤 참여 정보 부재를 `false`로 치환하지 않는다. 현재 membership의 유효한 참여 대상 행을 기준으로 조회한다.

### 6.4 최근 요약과 연속 참여

최근 요약의 분모는 `ATTENDED`와 `ABSENT`처럼 출석이 확정된 회차 수다. `UNKNOWN`은 타임라인에 `미확인`으로 표시하지만 분모에 넣지 않는다.

- 미확정이 없으면: `최근 N회 중 M회 함께했어요`
- 미확정이 있으면: `최근 확인된 N회 중 M회 함께했어요`
- 확정 상태가 없으면: 최근 요약 대신 `출석 확인을 기다리고 있어요`

연속 참여는 최신 참여 대상 회차부터 과거 방향으로 계산한다.

1. 최신 상태가 `UNKNOWN`이면 연속 참여 문구를 표시하지 않는다.
2. 최신 상태가 `ABSENT`이면 현재 연속 참여는 0이며 문구를 표시하지 않는다.
3. 최신 상태가 `ATTENDED`이면 첫 `ABSENT` 또는 `UNKNOWN` 전까지 연속된 `ATTENDED`를 센다.
4. 연속 횟수가 2 이상일 때만 `현재 N회 연속 참여`를 표시한다.

이 규칙은 미확정 상태를 불참이나 참여로 추정하지 않는다.

### 6.5 읽기 진행 상태

각 타임라인 회차의 보조 문구는 다음과 같다.

- `ATTENDED`이고 읽기 진행률이 100 이상: `완독`
- `ATTENDED`이고 읽기 진행률이 1~99: `N%`
- `ATTENDED`이고 읽기 진행률이 0 또는 없음: 별도 진행 문구 없음
- `ABSENT`: `불참`; 읽기 진행률은 표시하지 않음
- `UNKNOWN`: `미확인`; 읽기 진행률은 표시하지 않음

## 7. 다음 참여 안내

참여 안내는 홈의 세부 준비 작업을 복제하지 않는다. RSVP, 질문 부족 수, 읽기 페이스는 계속 멤버 홈이 담당한다.

내 공간에서는 다음 조건을 모두 만족할 때만 참여 안내와 `이번 세션 보기`를 제공한다.

- 현재 열린 세션이 존재
- membership 상태가 `ACTIVE`
- 현재 세션에 대한 멤버 앱 접근이 허용

문구는 현재 연속 참여에 따라 달라진다.

- 연속 참여 2회 이상: `다음 모임에도 함께하면 N회 연속 참여가 됩니다.`
- 그 외: `다음 모임부터 새로운 참여 흐름을 이어가 보세요.`

VIEWER, SUSPENDED, LEFT, INACTIVE 상태에는 쓰기 행동을 암시하는 참여 CTA를 표시하지 않는다. 현재 세션이 없을 때도 CTA를 만들지 않는다.

## 8. 프런트엔드 구성과 데이터 흐름

### 8.1 Route

`my-page-data.ts`는 기존처럼 프로필과 개인 여정 요약을 병렬로 불러온다.

- 프로필: 가입 시점, 현재 세션 ID, 최근 참여 대상 회차
- 개인 여정: 전체 참여, 완독, 질문, 서평 summary

최근 책 목록을 렌더링하지 않으므로 `fetchMyJourney`는 `limit: 1`로 요청하고 전체 수치는 서버 summary를 사용한다. 응답의 item은 내 공간 UI에서 렌더링하지 않는다. 프런트는 일부 page 길이로 전체 통계를 추정하지 않는다.

`MyPageRoute`는 기존 인증 route 계층의 `LogoutButton`을 구성하고, UI에는 `logoutControl` prop으로 전달한다. UI 계층은 auth API 또는 route module을 직접 import하지 않는다.

### 8.2 Model

`my-reading-shelf-model.ts`의 순수 계산은 다음을 담당한다.

- 가입 기간 문구
- 최근 확정 참여 횟수
- 최근 참여 요약 문구
- 연속 참여 횟수
- 회차별 출석 및 읽기 진행 표시
- membership 및 현재 세션 상태에 따른 참여 안내
- 이력이 없는 상태

날짜 의존 계산은 테스트에서 고정할 수 있도록 현재 날짜를 입력으로 받는다. React, router, API client 또는 TanStack Query를 import하지 않는다.

### 8.3 UI

UI는 다음 단위로 나눈다.

- `ParticipationAchievement`: 전체 참여와 함께한 기간
- `ParticipationTimeline`: 최근 참여 대상 회차 목록
- `ParticipationNudge`: 조건부 다음 참여 안내
- `SupportingReadingStats`: 완독, 질문, 서평
- `MemberSpaceAccountActions`: 전달받은 로그아웃 control 배치

UI는 계산된 view model과 callback 또는 control만 렌더링한다. API 호출과 navigation 정책을 소유하지 않는다.

## 9. 빈 상태와 오류 상태

### 9.1 참여 이력 없음

전체 참여와 최근 참여 대상 회차가 모두 없으면 0으로 채운 통계판과 빈 타임라인을 표시하지 않는다.

- 제목: `첫 참여부터 이곳에 흐름이 쌓여요`
- 열린 세션과 쓰기 권한이 있으면: `이번 세션 보기`
- 그 외: 설명만 표시

질문이나 서평만 존재해 개인 여정 summary가 0이 아니면 해당 보조 성취는 숨기지 않는다.

### 9.2 부분 이력

최근 참여 대상이 6회 미만이면 존재하는 회차만 렌더링한다. 빈 회차를 만들거나 가입 전 회차를 채우지 않는다.

### 9.3 필수 데이터 실패

프로필 또는 개인 여정 summary를 불러오지 못하면 기존 route error boundary를 사용한다. 한 응답의 일부 값을 다른 endpoint 값으로 추정해 화면을 만들지 않는다.

## 10. 로그아웃

로그아웃은 페이지 맨 아래 `계정` 구획에 둔다.

- 데스크톱: 설명 오른쪽의 낮은 위계 outline button
- 모바일: 최소 44px 높이의 전체 너비 outline button
- 확인 modal은 추가하지 않음
- 처리 중: `로그아웃 중`, button 비활성화
- 실패: button 가까이에 `role="alert"` 오류를 표시하고 현재 화면 유지
- 성공 또는 이미 만료된 401: 기존 auth logout 동작을 완료하고 공개 홈 `/`으로 hard navigation

기존 검증된 auth route/UI logout component를 재사용한다. 내 공간 UI에 별도 fetch 또는 중복 로그아웃 상태를 구현하지 않는다.

## 11. 시각·반응형·접근성

- 전체 성취 → 최근 참여 흐름 → 참여 안내 → 보조 성취 → 전체 기록 → 계정 순서를 데스크톱과 모바일에서 동일하게 유지한다.
- 하나의 반응형 semantic DOM을 사용한다.
- 최근 흐름은 장식용 chart가 아니라 회차별 상태를 읽을 수 있는 목록으로 구현한다.
- 참여, 불참, 미확인은 기호와 텍스트를 함께 사용하며 색상에만 의존하지 않는다.
- 불참을 경고색, 실패 문구 또는 감점처럼 표현하지 않는다.
- `이번 세션 보기`, `내 기록 전체 보기`, `로그아웃`은 최소 44px 조작 영역을 확보한다.
- 긴 한국어·영어 문구, 200% 확대 및 좁은 모바일 화면에서 겹침과 가로 스크롤을 만들지 않는다.
- 키보드 focus가 문서 순서와 일치하고 focus indicator가 보인다.
- 애니메이션은 필수가 아니며 새 motion을 추가하지 않는다.

## 12. 검증

### 12.1 서버

focused persistence/API tests는 다음을 증명한다.

- 중간 합류자의 가입 전 회차 제외
- 현재 membership이 참여 대상이 아니었던 회차 제외
- `participation_status != ACTIVE` 회차 제외
- `ATTENDED`, `ABSENT`, `UNKNOWN` 보존
- 다른 클럽과 다른 membership 격리
- 최근 참여 대상 최대 6개 및 정렬
- 기존 `attended` 호환 필드 유지

서버 변경은 archive read-side 경계 안에 두고 다음 canonical gate를 실행한다.

```bash
./scripts/server-ci-check.sh
./server/gradlew -p server integrationTest
```

### 12.2 프런트엔드

순수 model tests는 다음을 증명한다.

- 0회, 1~5회, 6회 이력
- 전체 참여와 최근 참여의 분리
- 최신 `ATTENDED`, `ABSENT`, `UNKNOWN`별 연속 참여
- 중간의 `UNKNOWN`에서 연속 계산 중단
- 미확정 분모 제외
- 가입 기간 경계와 잘못된 `joinedAt`
- membership 및 현재 세션별 참여 CTA
- 읽기 진행 표시 규칙

component/route tests는 다음을 증명한다.

- 최근 책별 기록 제거
- 전체 기록 링크 유지
- desktop/mobile에서 동일한 semantic 순서
- 출석 상태를 텍스트로 확인 가능
- 44px 조작 영역과 keyboard focus
- 로그아웃 성공, 401, 실패 및 중복 요청

frontend canonical gate는 다음과 같다.

```bash
pnpm --dir front lint
pnpm --dir front test
pnpm --dir front build
pnpm --dir front test:e2e
```

E2E는 다음 사용자 흐름을 포함한다.

- 내 공간 → 이번 세션
- 내 공간 → 내 책별 기록 전체 보기
- 중간 합류 fixture에서 가입 전 회차가 불참으로 보이지 않음
- 출석 미확정이 불참 또는 연속 참여로 계산되지 않음
- desktop/mobile 정보 순서와 로그아웃

## 13. 변경 표면과 위험

예상 변경 표면:

- server archive my-page read projection 및 API DTO
- frontend archive API contract, pure model, route composition, UI 및 style
- focused server/frontend tests와 member E2E fixture
- `CHANGELOG.md`와 구현 후 필요한 active architecture 문서

새 migration, BFF route, trusted header, auth 정책 또는 배포 설정 변경은 없다.

주요 잔여 위험은 기존 `recentAttendances` 소비자가 `attended`만 사용하는 경우다. 이 변경에서는 기존 필드를 유지하고 `attendanceStatus`를 추가해 호환성을 보존한다. 구현 계획에서 repository-wide consumer scan과 contract fixture 검증을 명시한다.

## 14. 승인된 결정 요약

- 중심 가치: 과거의 나와 비교하며 꾸준함을 느끼는 개인 회고
- 통계 범위: 전체 누적 + 최근 참여 대상 최대 6회
- 우선순위: 참여 꾸준함, 완독·질문·서평은 보조
- 표현: 참여 여정형, 경쟁·순위·배지·차트 없음
- 상세 기록: 내 공간에서 제거하고 `/app/me/records`에 유지
- 참여 안내: 열린 세션과 쓰기 권한이 있을 때만 제공
- 중간 합류: 가입 전 및 비대상 회차를 분모·불참·연속 참여에서 제외
- 출석 미확정: 별도 상태로 보존하고 불참으로 추정하지 않음
- 로그아웃: 페이지 맨 아래의 조용한 계정 동작
