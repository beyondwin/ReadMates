# ReadMates Host Meeting Operating Ledger Design

작성일: 2026-08-21
상태: APPROVED DESIGN SPEC
대상 표면: host 운영 UI, session lifecycle, session-import, 멤버 빈 화면 카피, architecture docs

이 문서는 승인된 제품 설계다. 현재 동작의 source of truth는 코드와 `docs/development/architecture.md`다. 구현이 끝나면 architecture와 운영 카피를 이 설계에 맞게 갱신한다.

## 1. 배경

호스트가 모임을 만들고, 열고, 마치고, 기록을 남기고, 다음 책을 등록하는 일은 이미 있다. 화면이 그 일을 한 흐름으로 보여 주지 않는다.

지금 운영자는 같은 모임을 서로 다른 축으로 다룬다.

- 서버 상태 `DRAFT → OPEN → CLOSED → PUBLISHED`와 한 단계 되돌리기
- 에디터 탭 개요 / 기본 정보 / 출석 / 기록 작업대 / 변경 기록
- 기록 입력 직접 작성 / AI / 외부 JSON, 그 위 작성 중과 적용본
- 만들기는 `/sessions/new`, 열기는 대시보드, 마감·공개는 개요, 점검은 `/closing`, 알림은 다른 페이지

피드백은 파일 이름·문서 제목·Markdown 세 칸과 기록 작업대 안에 있다. 실제 운영은 녹음을 밖에서 정리한 `readmates-session-import:v1` JSON을 올리는 일이다. 그 JSON에 요약, 하이라이트, 한줄평, 피드백이 같이 들어 있다.

마감 직후 멤버 홈은 「아직 열린 세션이 없습니다」만 보여 준다. 다음 책이 이미 있어도 현재 모임 화면은 막다른 골목이다. 다음 모임은 별도로 만들어야 하고, 여러 권을 미리 쌓아 두는 일이 주 경로가 아니다.

운영자 말 「세션」「회차」「기록 작업대」「반영 검토」는 처음 쓰는 호스트에게 낯설다.

## 2. 목표

- 처음 보는 호스트가 `/app/host`에서 만들기 → 열기 → 마치기 → 다음 책 등록 → 정리본 올리기 → 반영 → 공개까지 한 장부로 끝낸다.
- 마감 다음 화면에 이번 모임 정리와 다음에 읽을 책 목록이 함께 있다. 기록은 미뤄도 된다.
- 다음에 읽을 책은 여러 권 미리 넣을 수 있고, 권마다 멤버에게 보일지를 고른다.
- 잘못된 열기·마치기·공개는 같은 화면에서 한 단계 되돌린다. 준비 중인 모임은 목록에서 지울 수 있다.
- 기록과 피드백의 주 입력은 정리본(JSON) 올리기다. 직접 타이핑과 앱 안 녹음→LLM은 주 경로가 아니다.
- 새 모임 폼은 이 클럽 최근 최대 10모임의 반복 값만 채운다. 책은 채우지 않는다.
- 화면에 쓰는 말은 「모임」이다. 내부 상태 이름은 내지 않는다.

성공 기준:

- 호스트가 모임을 마치면 그 모임 화면의 모임 후 단계에 남고 `/sessions/new`로 달아나지 않는다.
- 다음에 읽을 책이 두 권 이상 있어도 날짜 순 목록으로 보이고, `GUEST_READABLE`인 책만 멤버 예정 목록에 나간다.
- 정리본을 올리면 preview 뒤 작성 중 초안에 요약·하이라이트·한줄평·피드백이 같이 들어간다.
- 진행 중 모임이 없고 멤버에게 보이는 다음 책이 있으면, 멤버 홈은 막다른 「열린 모임 없음」만 남기지 않는다.
- 열기에도 확인 창을 쓴다. 브라우저 `confirm()`은 쓰지 않는다.

## 3. Non-goals

- 클럽당 진행 중 모임(`OPEN`) 두 개, 현재 모임을 한 명령으로 교체
- `PUBLISHED → OPEN` 같은 두 단계 점프
- 알림 회수, 이메일 unsend, inbox 삭제
- 기록·참석·질문 row 삭제, 새 세션 상태 값, lifecycle 감사 원장
- 다음에 읽을 책 끌어 바꾸기. 순서는 날짜가 정한다
- 공개 사이트(`PUBLIC_RECORD`)에 다음 책을 미리 올리기. 멤버·손님 앱 예정 목록만 다룬다
- 앱이 녹음 파일을 LLM API로 보내는 기능. 이미 있는 in-app AI 탭을 이 한 바퀴의 주 버튼으로 올리는 일. 둘 다 나중 항목이다
- 피드백 직접 입력 칸(큰 텍스트 영역)을 주 경로로 두는 일
- 멤버 앱·게스트 앱의 정보 구조 재설계. 빈 현재 모임 카피와 예정 목록 연결만 허용
- V45 `visibility` / `is_public` dual-write 제거
- BFF 정책 변경. 브라우저는 기존 same-origin `/api/bff/**`로 호출한다

## 4. 선택한 접근

호스트 홈을 지표판이 아니라 **지금 다루는 한 모임 장부**로 바꾼다. 위쪽에 모임 전 / 진행 중 / 모임 후 한 줄이 있고, 단계마다 다음 행동 하나만 크게 둔다.

서버 상태와 한 `OPEN` 규칙은 유지한다. 화면이 기존 API를 운영 순서에 맞게 부를 뿐이다.

검토한 대안:

1. **회차 운영 장부** — 선택. 한 모임이 주인공이고 마감 후 이번 정리와 다음 책 목록이 같은 단계에 있다.
2. **전 구간 위저드** — 첫 사용은 쉽고 출석 수정·되돌리기가 답답하다.
3. **대시보드 안내만** — 범위는 작고 기록 작업대·피드백의 막힘은 남는다.

## 5. 단계와 홈이 고르는 모임

| 운영자가 보는 단계 | 서버 상태 | 이 단계에서 하는 일 |
| --- | --- | --- |
| 모임 전 | `DRAFT` | 책·날짜·공개 범위, 멤버에게 열기 |
| 진행 중 | `OPEN` | 출석·참석 여부 확인, 모임 마치기, 다음에 읽을 책 목록 |
| 모임 후 | `CLOSED` 또는 `PUBLISHED` | 출석 수정, 정리본 올리기, 반영, 기록 공개, 다음에 읽을 책 목록 |

홈(`/app/host`)이 고르는 모임:

1. `OPEN`이 있으면 그 모임 (진행 중)
2. 없으면 날짜가 가장 가까운 `DRAFT` (모임 전)
3. 그것도 없으면 가장 최근 `CLOSED`
4. 없으면 「첫 모임 만들기」

마감하면 그 모임의 **모임 후**에 남는다. 다음 책을 만들어도 주소가 새 모임으로 바뀌지 않는다. 홈이 규칙 2로 다음 `DRAFT`를 고를 때, 이전 모임의 정리본이 아직 없으면 상단에 「이전 모임 기록 남음」 링크만 둔다.

장부에서 과거 모임을 열면 같은 장부 표면이다.

## 6. 주소

기존 주소를 살리고 주 경로만 바꾼다.

| 주소 | 역할 |
| --- | --- |
| `/app/host` | 지금 다루는 모임 장부 |
| `/app/host/sessions/:sessionId` | 같은 장부, 특정 모임. canonical |
| `/app/host/sessions/:sessionId/edit` | canonical로 보낸다. `section` query는 단계로 해석한다 |
| `/app/host/sessions/new` | 모임 전 빈 장부. 홈 빈 화면과 같은 폼 |
| `/app/host/sessions/:sessionId/closing` | 그 모임 모임 후로 보낸다 |
| `/app/host/sessions` | 과거·검색 장부. 보조 |
| 알림·멤버·초대 | 유지. 이 한 바퀴의 필수 칸이 아니다 |

`/edit?section=records`는 모임 후 정리본 영역으로 보낸다. `/edit?records=json`과 `/edit?aigen=1`도 같은 모임 후 정리본 영역으로 보내되, aigen은 주 버튼으로 노출하지 않는다.

## 7. 첫 운영 한 바퀴

단계마다 다음 행동 하나. 부가 설정은 접는다.

**모임 전.** 필수는 책 제목·저자·날짜다. 시간은 자동 채움 또는 20:00–22:00, 장소는 온라인이 기본이다. 접속 주소와 멤버에게 보이기는 펼친다. 저장 후 주 버튼은 「멤버에게 열기」다. 확인 뒤에만 `OPEN`이 된다.

**진행 중.** 책·일시, 참석 요약, 출석 목록, 다음에 읽을 책. 주 버튼은 「모임 마치기」다. 기본 정보 수정은 같은 화면, 기록 미리 쓰기는 보조다. 마감도 확인 뒤다.

**모임 후.** 데스크톱은 두 열, 모바일은 한 열이다.

- 이번 모임 정리: 출석, 정리본 올리기, 반영 전 확인, 기록 공개
- 다음에 읽을 책: 날짜 순 목록과 「모임 하나 더」

모바일에서 다음 책이 없으면 「모임 하나 더」를 위에 둔다. 있으면 이번 정리를 위에 두고 다음 책은 짧은 목록이다.

기록 공개는 기존 자격을 유지한다. `CLOSED` + `GUEST_READABLE` + 비어 있지 않은 공개 요약. 막히면 버튼 아래 이유 한 줄이다.

## 8. 다음에 읽을 책

`DRAFT` 여러 개를 날짜 순 목록으로 쌓는다. 「모임 하나 더」는 목록에만 넣는다. 바로 열지 않는다. 홈이 다음에 다루는 모임은 가장 가까운 `DRAFT`다.

각 줄에 「멤버에게 보이기」 스위치가 있다. 켜면 `access_scope=GUEST_READABLE`이고 멤버·손님 예정 목록에 나간다. 끄면 `HOST_ONLY`다. 공개 사이트 배치(`site_visibility`)는 이 스위치가 건드리지 않는다.

새로 넣을 때 스위치 기본값은 최근 10모임의 `access_scope` 과반이다. 과반을 못 정하면 `HOST_ONLY`다.

멤버 현재 모임이 없고 `GUEST_READABLE`인 `DRAFT`가 있으면, 멤버·게스트 현재 화면은 「아직 열린 모임이 없습니다」만 남기지 않고 예정 책 목록을 이어서 보여 준다. RSVP·질문은 여전히 진행 중 모임에서만 연다.

## 9. 자동 채움

호스트 전용 `GET /api/host/sessions/schedule-defaults`가 이 클럽 최근 최대 10모임을 날짜 내림으로 읽어 제안만 반환한다. 다른 클럽 데이터는 쓰지 않는다. 책 제목·저자·표지·요약·하이라이트·한줄평·피드백은 넣지 않는다.

| 칸 | 규칙 |
| --- | --- |
| 시간 | 같은 시작·끝이 과반이면 그 값, 아니면 바로 이전 모임 |
| 장소 | 같은 방식 |
| 접속 주소·암호 | 바로 이전 모임에 주소가 있으면 그 모임 값을 함께 복사. 암호만 따로 추측하지 않음 |
| 멤버에게 보이기 | 최근 10모임 `access_scope` 과반. 없으면 호스트만 |
| 질문 마감 | 모임 전날 밤이 과반이면 그 간격 |
| 다음 날짜 | 최근 간격의 중앙값. 요일이 과반이면 그 요일에 맞춤. 과거 모임이 하나면 날짜는 비우고 시간·장소만 복사 |
| 표시 보조 | 번호는 서버 `max(number)+1`. 제목 칸을 운영 화면에 필수로 두지 않고 책 제목을 제목으로 쓴다 |

과거가 없거나 이 API가 실패하면 저녁 8–10시·온라인으로 폼만 채우고 만들기는 막지 않는다. 호스트가 이미 친 칸은 덮지 않는다. 접속 암호는 폼 응답에만 넣고 로그·메트릭 라벨에는 넣지 않는다. 힌트는 한 줄이다. 예: `이전 모임과 같은 시간으로 넣었습니다.` 자동 채움 설정 화면은 만들지 않는다.

「모임 하나 더」의 날짜 간격은 목록의 마지막 날짜와 최근 모임 이력을 함께 본다.

## 10. 운영자에게 보이는 말

내부 enum과 기술 이름을 화면에 내지 않는다.

| 화면 | 쓰지 않는 말 |
| --- | --- |
| 모임 | 세션, 회차 |
| 모임 전 / 진행 중 / 모임 후 | DRAFT, OPEN, CLOSED, PUBLISHED, 클로징 |
| 멤버에게 열기 | 세션 시작, open, 현재로 시작 |
| 모임 마치기 | 세션 마감, 닫기 |
| 다음에 읽을 책 | 예정 세션 큐 |
| 멤버에게 보이기 | GUEST_READABLE, 게스트 공개 |
| 호스트만 | HOST_ONLY |
| 정리본 올리기 | 기록 작업대, 외부 JSON, session-import |
| 작성 중 / 멤버에게 보이는 기록 | 초안 / 적용본 |
| 반영 전 확인 | 반영 검토 |
| 기록 공개 | 세션 공개 |
| 참석 여부 | RSVP |
| n번째 · 날짜 | n회차 |

확인 창 본문은 한 줄로 결과를 말한다. 예: `모임을 마치면 참석과 질문이 멈춥니다. 기록은 남습니다.`

번호는 제목이 아니라 보조 줄이다. `3번째 · 3월 18일`.

## 11. 수정과 되돌리기

책·날짜·장소는 그 장부에서 바로 고친다. 단계 되돌리기는 주 버튼 옆의 약한 버튼이다. 확인 창은 기존 lifecycle 확인 패턴을 쓴다.

| 지금 단계 | 되돌리기 | API |
| --- | --- | --- |
| 진행 중 | 모임 전으로 되돌리기 | `POST .../return-to-draft` |
| 모임 후 · 아직 기록 공개 전 | 다시 진행 중으로 | `POST .../reopen` |
| 모임 후 · 기록 공개됨 | 공개 취소 | `POST .../unpublish` |
| 모임 전 | 목록에서 지우기 | 아래 삭제 |

지금 삭제는 `OPEN`만 가능하다. 이 설계는 **기록 revision이나 알림 결정이 없는 `DRAFT` 삭제**를 연다. 미리보기와 확인은 기존 삭제 dialog 패턴을 쓴다. `OPEN`이면서 내구 이력이 있는 모임 삭제는 지금 규칙을 유지한다.

다른 진행 중 모임이 있어 열기·다시 진행이 막히면 확인 창에 그 모임으로 가는 링크를 남긴다. `SESSION_OPEN_ALREADY_EXISTS`와 `openSessionId`를 쓴다.

## 12. 정리본과 피드백

주 입력은 기존 `readmates-session-import:v1` JSON 하나다. 운영 화면 이름은 「정리본 올리기」다.

흐름:

1. 파일을 놓거나 고른다
2. 기존 preview API로 모임 번호·책·날짜·참석자 이름 일치를 확인한다
3. commit이 공통 `session_record_drafts`를 교체한다. 요약, 하이라이트, 한줄평, 피드백 문서가 같이 들어간다
4. 「반영 전 확인」에서 항목 수를 보여 주고, 맞으면 기존 apply가 live 기록과 피드백을 갱신한다
5. 그다음 「기록 공개」

파일 이름, 문서 제목, Markdown 라벨은 주 화면에 내지 않는다. 가져온 뒤 틀린 문장만 고칠 수는 있다. 닫기·Escape·나중에는 apply를 만들지 않는다.

직접 작성은 가져온 뒤 고치기용 보조다. 큰 빈 피드백 칸을 첫 화면의 주 버튼으로 두지 않는다.

앱이 녹음 파일을 LLM에 보내는 기능은 구현하지 않는다. 이미 있는 in-app AI 탭은 제거하지 않아도 되지만, 이 한 바퀴의 주 버튼·필수 칸이 아니다. 후속 spec에서 녹음→LLM을 다룰 때 정리본과 같은 작성 중 경계로 합친다.

`HOST_ONLY`에서는 지금처럼 정리본 저장을 거절한다. 모임 후 정리 전에 멤버·손님도 보기로 바꿀 수 있어야 하고, 거절 시 그 이유를 한 줄로 말한다.

## 13. 데이터 흐름

서버 상태 기계와 권한은 유지한다. 새 영속 상태 값은 없다. 스키마 변경은 없다.

읽기: 홈은 현재 모임·목록·대시보드를 같이 읽고, 고르는 규칙은 프론트 모델이다. 모임 후 점검 항목은 있는 closing-status 읽기를 이 화면에 붙일 수 있다. `/closing` 주소만 리다이렉트한다.

쓰기:

- 만들기·다음 책: `POST /api/host/sessions`
- 기본 정보: 기존 update
- 멤버에게 보이기: 기존 `PATCH /api/host/sessions/{sessionId}/access-scope`
- 열기·마치기·공개·되돌리기: 기존 lifecycle. 열기도 확인 창
- 정리본: 기존 `/session-import/preview`, `/session-import/commit`, session-record apply
- 출석: 기존 attendance. 마친 뒤에도 수정 가능

추가 API:

- `GET /api/host/sessions/schedule-defaults` — 호스트 전용 제안
- `DRAFT` 삭제 — 기존 삭제 preview/delete를 `DRAFT`이면서 내구 이력이 없을 때로 확장

마감 뒤 캐시 무효화는 기존 lifecycle 규칙을 따른다. 상태가 바뀐 경우에만 멤버 current/upcoming과 공개 캐시를 지운다.

BFF는 path allowlist가 막혀 있으면 defaults와 DRAFT 삭제만 연다. 새 인가 정책은 없다.

## 14. 실패

- 정리본 preview 실패: 파일 칸에 한 줄. 예: 책 제목이 이 모임과 다릅니다
- 기록 공개 거절: 버튼 아래 한 줄. 예: 공개 요약이 없습니다
- 이미 진행 중인 모임: 확인 창에 그 모임 링크
- schedule-defaults 실패: 기본 시간·장소만 채우고 만들기는 계속
- 네트워크 오류: 그 칸만 다시 시도
- 열기·마치기·공개·되돌리기·삭제는 확인 없이 보내지 않는다

## 15. 검증

Acceptance matrix: Session lifecycle, Guest/public exposure, Actor/authorization, UI/runtime state. BFF 신규 인증 없음. Persistence/migration 없음. Cursor collection 제외. 정리본은 기존 session-import 계약을 재사용하므로 import 자격 테스트를 회귀로 돌린다.

서버:

- schedule-defaults가 클럽을 넘지 않음, 최대 10개, 책·피드백 미포함, 암호는 응답 필드 외에 없음
- `DRAFT` 삭제 성공/내구 이력 거절, `OPEN` 삭제 기존 규칙 유지
- 기존 open/close/publish/reopen/unpublish/return-to-draft 회귀

프론트 모델:

- 홈이 고르는 모임 순서
- 다음에 읽을 책 목록과 보이기 스위치 카피
- 단계별 주 버튼·되돌리기 라벨
- 멤버 빈 현재 모임 + 예정 책 연결
- `/edit`·`/closing` 이동

프론트 UI:

- 정리본 올리기가 모임 후 주 경로, 파일 이름/Markdown 주 화면 비노출
- 열기 확인 창
- 모바일에서 다음 책이 없을 때 폼이 위

E2E 한 바퀴: 만들기 → 열기(확인) → 마치기 → 다음 책 두 권 중 하나만 멤버에게 보이기 → 정리본 업로드·반영 → 홈이 가까운 다음 모임 전으로 가고 이전 기록 링크가 있음.

명령: 프론트 포커스 lint/test 후 `pnpm --dir front lint`, `pnpm --dir front test`, `pnpm --dir front build`. 서버는 defaults·삭제 포커스 후 `./scripts/server-ci-check.sh`. 한 바퀴가 늘면 `pnpm --dir front test:e2e`의 host session 수명 시나리오를 확장한다.

## 16. 구현 슬라이스

한 spec, 구현은 이 순서로 나눈다. 슬라이스마다 기존 API 계약을 깨지 않는다.

1. 장부 셸, 단계 한 줄, 쉬운 말, `/edit`·`/closing` 이동
2. 모임 전·진행 중·모임 후 주 버튼, 열기 확인
3. 다음에 읽을 책 목록, 멤버에게 보이기, `DRAFT` 삭제, 멤버 빈 화면 연결
4. schedule-defaults와 새 모임·하나 더 폼 채움
5. 모임 후 주 경로를 정리본 올리기·반영 전 확인으로 모음

## 17. 구현 시 주의

- `OPEN + PUBLIC_RECORD` 불변식은 유지한다. 다시 진행 중으로 바꿀 때 기존 `reopen`의 `HIDDEN` 전환을 빠뜨리지 않는다.
- 멤버에게 보이기는 app access만 바꾼다. 공개 사이트 query는 `PUBLISHED + PUBLIC_RECORD`만 반환한다.
- 정리본 commit은 live를 직접 바꾸지 않는다. apply가 expected draft/live revision을 검증한다.
- 예시에 실제 멤버 데이터, 비밀, 사설 도메인, 로컬 절대 경로를 넣지 않는다.
- 화면 카피에서 「세션」「회차」를 새 주 경로에 다시 넣지 않는다. 서버 JSON 필드명은 유지한다.
