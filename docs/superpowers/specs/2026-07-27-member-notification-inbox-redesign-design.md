# 멤버 알림함 UI 리디자인

## 배경

현재 멤버 알림함은 큰 문서형 헤더, 목록 패널, 개별 카드가 중첩되어 실제 정보량에 비해 지나치게 많은 공간을 사용한다. 각 항목의 본문과 동작은 짧지만 카드가 화면 너비를 모두 차지해 탐색 밀도가 낮고 스크롤이 길다.

또한 `Open`, `View feedback`, `Past session reflection` 같은 영어 액션과 배지가 한글 인터페이스에 섞여 있다. 별도의 `읽음` 버튼, `읽지 않음` 문구, 강조 막대도 같은 상태를 반복해서 표현한다. 이 구조는 ReadMates 멤버 화면의 차분한 개인 독서 책상 톤보다 관리용 대시보드에 가깝다.

## 목표

- 데스크톱에서 알림 7~9개를 빠르게 훑을 수 있는 밀도를 만든다.
- 큰 카드 중첩을 없애고 따뜻한 종이 표면, 잉크색 위계, 절제된 구분선으로 ReadMates의 편집형 톤을 유지한다.
- 사용자에게 보이는 알림함 문구를 한국어로 통일한다.
- 행 전체를 명확한 탐색 동작으로 만들고 읽음 상태 표현을 단순화한다.
- 기존 읽음 처리, 모두 읽음, 페이지네이션, 안전한 딥링크, 지난 모임 복귀 상태는 유지한다.
- 데스크톱과 모바일 모두에서 같은 정보 순서와 기능을 제공한다.

## 비목표

- 알림 API, 서버 저장 구조, 이벤트 발송 파이프라인을 변경하지 않는다.
- 알림 필터, 검색, 삭제, 보관, 일괄 선택 기능을 추가하지 않는다.
- 알림 제목과 본문을 서버에서 다시 작성하거나 번역하지 않는다.
- 멤버 홈, 호스트 알림 발송 화면, 플랫폼 관리자 알림 화면을 함께 재설계하지 않는다.

## 검토한 접근

### A. 간결한 편집형 목록 — 채택

제목과 새 알림 개수를 작은 헤더에 두고, 알림은 카드 없이 얇은 구분선으로 이어지는 단일 목록으로 표시한다. 새 알림은 점의 유무와 제목 굵기로 구분하고, 행 전체를 눌러 관련 화면으로 이동한다.

ReadMates의 조용한 편집형 톤을 가장 잘 유지하면서 현재의 과도한 높이와 긴 스크롤을 직접 해결한다.

### B. 새 알림 중심 그룹형

`새 알림`과 `이전 알림`을 별도 구획으로 분리한다. 읽지 않은 항목은 더 분명하지만 구획 제목과 개수 표시가 반복되어 A안보다 화면이 무거워진다.

### C. 독서 흐름 타임라인

알림을 시간축에 배치해 기록이 쌓이는 인상을 강화한다. 시각적 개성은 크지만 각 이벤트에 별도 상자가 필요해 항목 높이를 줄이기 어렵다.

## 화면 구조

### 페이지 폭과 헤더

- 목록 본문은 데스크톱에서 최대 약 `880px` 너비로 제한하고 중앙에 둔다.
- 기존의 큰 문서 패널을 제거한다.
- 헤더에는 작은 맥락 문구 `읽는사이 · 알림`, 제목 `알림`, `새 알림 N개`, `모두 읽음`만 남긴다.
- 제목은 멤버 홈과 같은 편집형 서체 위계를 사용하되 현재보다 작게 표시한다.
- `모두 읽음`은 채워진 버튼이 아니라 눈에 띄되 절제된 텍스트 버튼으로 제공한다.

### 알림 행

각 행은 다음 순서로 구성한다.

1. 읽지 않은 상태 점 또는 같은 폭의 빈 자리
2. 알림 종류와 생성 시각
3. 제목
4. 최대 두 줄의 본문
5. 이동 가능함을 나타내는 우측 화살표

개별 행에는 외곽 카드, 영어 액션, 회고 배지, 별도의 `읽음` 버튼을 두지 않는다. 행 사이에는 얇은 구분선만 사용한다. 기본 높이는 약 `76~88px` 범위이며 본문이 길 때만 두 줄까지 늘어난다.

### 상태 표현

- 읽지 않은 행은 남색 점의 존재와 조금 더 강한 제목 굵기로 구분한다.
- 읽은 행은 점 자리를 유지하되 시각적 점은 표시하지 않아 열 정렬이 흔들리지 않게 한다.
- 스크린리더에는 별도 비시각 문구로 `읽지 않음` 상태를 제공한다.
- 상태는 색상만으로 전달하지 않는다.

### 모바일

- 데스크톱과 동일한 정보 순서를 유지한다.
- 좌우 여백을 줄이고 각 행의 터치 영역을 최소 `56px` 이상 확보한다.
- 본문은 최대 두 줄로 제한하고 긴 한국어와 영어가 겹치거나 컨트롤을 밀어내지 않게 한다.
- `모두 읽음`은 제목과 같은 줄에 유지하되 좁은 화면에서는 자연스럽게 줄바꿈할 수 있다.
- 기존 모바일 헤더와 하단 탭 바를 그대로 유지한다.

## 컴포넌트 경계

### Route

`front/features/notifications/route/member-notifications-route.tsx`는 현재처럼 다음 책임을 유지한다.

- loader 결과와 추가 페이지 상태 관리
- 개별 읽음 처리와 모두 읽음 처리
- 처리 중 중복 동작 방지
- 읽음 처리 성공 후 관련 화면으로 이동
- 오류 상태와 재검증 관리

API 계약이나 라우트 경계를 변경하지 않는다.

### UI

`front/features/notifications/ui/member-notifications-page.tsx`는 전달받은 데이터와 콜백만 렌더링한다.

- 큰 인라인 스타일 블록을 알림함 전용 클래스 구조로 바꾼다.
- 읽은 알림은 일반 링크로, 읽지 않은 알림은 기존 `onOpenNotification` 흐름으로 연다.
- 별도의 `onMarkRead` 버튼 표면은 제거한다. 개별 읽음 처리는 읽지 않은 행을 여는 동작에 포함된다.
- 빈 상태, 오류, 추가 로딩 상태를 같은 목록 문법 안에서 표시한다.

### Link model

`front/features/notifications/model/notification-link-model.ts`는 안전한 경로 정규화와 복귀 상태만 담당한다.

UI에서 더 이상 사용하지 않는 영어 `primaryActionLabel`과 `reflectionLabel`은 제거한다. 지난 모임 복귀 상태의 한국어 라벨과 안전하지 않은 딥링크의 알림함 fallback은 유지한다.

## 상호작용과 데이터 흐름

### 알림 열기

1. 사용자가 알림 행을 마우스, 터치 또는 키보드로 연다.
2. 이미 읽은 알림이면 안전하게 정규화된 링크로 바로 이동한다.
3. 읽지 않은 알림이면 route가 기존 개별 읽음 API를 호출한다.
4. 읽음 처리에 성공하면 loader 데이터를 재검증하고 관련 화면으로 이동한다.
5. 지난 모임 회고 대상이면 기존 복귀 상태를 함께 전달한다.

읽음 처리 중인 행은 중복 실행을 막고 `aria-busy` 또는 동등한 접근성 상태를 제공한다.

### 모두 읽음

1. 새 알림이 있을 때만 `모두 읽음`을 활성화한다.
2. 실행 중에는 `읽음 처리 중…`으로 바꾸고 중복 실행을 막는다.
3. 성공하면 목록 데이터를 재검증해 점과 개수를 갱신한다.

### 더 보기

기존 cursor 기반 페이지네이션을 유지한다. `더 보기`는 목록 하단의 조용한 텍스트 버튼으로 표시하고, 로딩 중에는 `불러오는 중…`으로 바꾼다.

## 오류와 빈 상태

- 개별 또는 전체 읽음 처리 실패 시 이동하지 않고 현재 읽음 상태를 유지한다.
- 오류는 헤더와 목록 사이의 작은 인라인 영역에 한국어로 표시하고 `role="alert"`를 유지한다.
- 추가 페이지 로딩 실패는 기존 항목을 보존하고 같은 오류 영역에서 재시도를 안내한다.
- 알림이 없으면 별도 중첩 카드 없이 목록 경계 안에 `아직 받은 알림이 없습니다`와 짧은 보조 문구를 표시한다.
- 안전하지 않거나 지원하지 않는 딥링크는 기존처럼 알림함으로 fallback한다.

## 접근성

- 각 행은 링크 의미를 가지며 Enter 키와 기본 브라우저 링크 동작을 지원한다.
- 전체 행에 명확한 `:focus-visible` 외곽선을 제공한다.
- 링크의 접근 가능한 이름은 제목과 읽지 않은 상태를 포함한다.
- 읽음 상태는 점의 존재, 제목 굵기, 비시각 문구를 함께 사용한다.
- 처리 중 상태는 버튼 비활성화와 접근성 속성으로 전달한다.
- WCAG AA 대비, 축소 모션 환경, 한국어·영어 줄바꿈을 유지한다.

## 검증

### 집중 테스트

- 한국어 문구만 렌더링되고 제거 대상 영어 문구가 나타나지 않는다.
- 읽지 않은 행 전체를 열면 읽음 처리 후 올바른 딥링크와 복귀 상태로 이동한다.
- 읽은 행은 기본 링크로 열린다.
- 모두 읽음의 활성화, 처리 중, 성공, 실패 상태가 올바르다.
- 빈 목록, 더 보기, 추가 로딩 실패가 조밀한 구조로 렌더링된다.
- 안전하지 않은 딥링크가 외부로 이동하지 않는다.
- 키보드 포커스와 접근 가능한 이름이 유지된다.

### 프런트엔드 게이트

```bash
corepack pnpm --dir front lint
corepack pnpm --dir front test
corepack pnpm --dir front build
corepack pnpm --dir front test:e2e
```

API와 인증 계약은 바뀌지 않지만 알림 행의 읽음 처리 후 이동이라는 사용자 흐름이 바뀌므로 E2E까지 확인한다.

### 수동 시각 검증

- 데스크톱에서 목록 밀도와 최대 너비를 확인한다.
- 모바일에서 제목, 본문 두 줄, 전체 읽음, 하단 탭 바가 겹치지 않는지 확인한다.
- 읽지 않음, 처리 중, 오류, 빈 상태를 각각 확인한다.
- 키보드만으로 모든 알림 행과 `모두 읽음`, `더 보기`에 접근할 수 있는지 확인한다.

## 수용 기준

- 큰 문서 패널과 중첩된 개별 카드가 사라진다.
- 일반적인 데스크톱 화면에서 알림 7~9개를 훑을 수 있다.
- 사용자에게 보이는 알림함 텍스트에 영어 액션이나 영어 회고 배지가 남지 않는다.
- 행 전체를 눌러 관련 화면으로 이동할 수 있다.
- 읽음 처리, 모두 읽음, 더 보기, 안전한 딥링크, 복귀 상태가 기존과 동일하게 동작한다.
- 데스크톱과 모바일 모두 명확한 위계, 안전한 줄바꿈, 키보드 포커스를 제공한다.
