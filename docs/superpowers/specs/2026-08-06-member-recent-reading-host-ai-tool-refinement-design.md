# 멤버 최근 독서 기록 및 호스트 AI 도구 정제 설계

## 배경

`/clubs/:slug/app/me`의 최근 독서 기록은 아카이브 세션 카드보다 표지가 작고, 회차 표기가 `7차`라서 같은 기록을 다루는 화면끼리 시각 문법이 다르다. `/clubs/:slug/app/host`의 AI 기본 모델 도구는 내부 배경색과 가로 여백 때문에 상위 운영 도구 구분선과 어긋나며, 위쪽 선이 겹쳐 보인다.

## 목표

- 최근 독서 기록을 아카이브의 모바일 세션 카드와 같은 `No.07 · YYYY.MM.DD` 메타, 표지 비율, 중앙 정렬, 얕은 책 그림자, 카드 여백으로 맞춘다.
- 최근 독서 기록의 개인 활동 정보인 `질문 N`, `서평 N`, `피드백 O/제한/준비중`은 그대로 유지한다.
- 아카이브 전용 정보인 참석 수와 공개 상태를 최근 독서 기록에 새로 추가하지 않는다.
- 호스트 AI 기본 모델 도구를 운영 장부의 한 행처럼 재구성해 중복 구분선과 좌우 inset 배경을 제거한다.
- AI capability, 로딩, 비활성, 오류, 저장 동작과 문구는 변경하지 않는다.

## 검토한 접근

### 1. 아카이브 컴포넌트를 직접 재사용

표지와 카드가 가장 빨리 같아지지만 아카이브 행은 참석·공개·피드백 상태와 route state를 함께 소유한다. 개인 활동 배지를 유지해야 하는 최근 독서 기록의 책임과 맞지 않아 제외한다.

### 2. 최근 기록 전용 마크업을 유지하며 시각 토큰만 정렬 — 채택

기존 링크 구조와 개인 활동 데이터를 보존하고, 회차 포맷·표지 렌더링·CSS만 아카이브의 시각 문법에 맞춘다. 데이터/권한 경계를 건드리지 않으면서 요청한 차이를 정확히 줄일 수 있다.

### 3. 공용 기록 카드 추상화 신설

장기적으로 중복을 줄일 수 있지만 두 화면의 상태 정보와 링크 계약이 달라 현재 범위에서는 과한 추상화다. 후속 화면까지 함께 이관하지 않는 한 도입하지 않는다.

## 상세 설계

### 최근 독서 기록

- `buildRecentReadingPreview`가 회차를 `No.`와 두 자리 숫자로 만든다. 예: `7`은 `No.07`, `12`는 `No.12`.
- 기존의 전체 행 링크와 빈 상태, 표지 오류 fallback을 유지한다.
- 표지는 기존 2:3의 작은 이미지 대신 프로젝트 공용 `BookCover`와 동일한 3:4 비율 및 깊이 표현을 사용한다. 카드 왼쪽 열 안에서 수직·수평 중앙에 배치한다.
- 데스크톱 행은 둥근 테두리 카드, 넉넉한 내부 여백, 표지–책 정보–활동 배지–chevron 순서를 사용한다.
- 모바일에서는 표지, 본문, chevron의 3열 구성을 유지하되 활동 배지는 본문 아래에서 자연스럽게 줄바꿈한다. 320px에서도 제목·저자·배지가 겹치지 않아야 한다.
- 배지 내용은 기존 view model이 만든 `질문 N`, `서평 N`, `피드백 O/제한/준비중`만 표시한다. 참석 수나 공개 상태는 추가하지 않는다.

### 호스트 AI 기본 모델 도구

- route의 외곽 `container`가 가로 정렬을 소유하고, 내부 도구는 별도 inset 배경 없이 전체 가용 폭을 쓴다.
- 도구 자체는 위쪽 선을 제거하고 아래쪽 구분선 하나만 사용해 직전 운영 도구 영역의 끝선과 겹치지 않게 한다.
- 활성 상태에서는 제목/설명, 모델 선택, 저장 액션을 한 장부 행의 3열로 배치한다.
- capability 확인 중, 비활성, 조회 실패 상태는 제목 아래의 차분한 상태 문장으로 유지한다. 상태 문구와 `role`/`aria-live` 계약은 바꾸지 않는다.
- 태블릿에서는 2열, 모바일에서는 1열로 접고 저장 버튼은 최소 44px 터치 높이를 확보한다.

## 접근성 및 상호작용

- 최근 기록은 기존 의미 구조인 `ol > li > a`와 각 링크의 접근 가능한 이름을 유지한다.
- 표지는 중복 낭독을 피하기 위해 장식 이미지로 유지하고 실패 시 로컬 fallback을 보여 준다.
- 키보드 focus outline과 reduced-motion에서 chevron 이동 비활성화를 유지한다.
- AI select/label 연결, disabled, loading, error, success 상태와 저장 가능 조건을 유지한다.
- 색상만으로 상태를 구분하지 않고 기존 배지 텍스트와 상태 문장을 보존한다.

## 테스트 및 검증

- 모델 단위 테스트에서 `No.07`/`No.12` 두 자리 회차 포맷을 고정한다.
- 최근 기록 컴포넌트 테스트에서 아카이브형 표지 wrapper, 개인 활동 배지 유지, 참석/공개 배지 부재를 검증한다.
- AI 기본 모델 컴포넌트 테스트에서 compact variant의 ledger class와 기존 capability/save 상태를 검증한다.
- 관련 Vitest를 RED/GREEN으로 실행한 뒤 frontend lint, 전체 test, build를 실행한다.
- 실제 로컬 route를 데스크톱과 모바일에서 한 번에 점검하고, 수정이 필요하면 한 차례 일괄 보정 후 확인한다.
- 변경된 UI 파일에 Impeccable detector를 한 번 실행한다.

## 비목표

- API, BFF, Spring 서버, 데이터베이스, 권한 또는 AI 모델 allowlist 변경
- 참석/공개 상태를 최근 독서 기록에 추가
- 아카이브 화면 자체의 재설계
- 실제 AI 생성 요청이나 저장 mutation 실행
