# 노트 필터와 아카이브 탭 UI 일치 설계

## 목적

클럽 노트의 `전체`, `하이라이트`, `한줄평`, `질문` 필터를 아카이브의 `세션`, `피드백 문서`, `내 질문`, `내 서평` 탭과 같은 선택 표현으로 맞춘다. 사용자가 두 읽기 화면에서 동일한 방식으로 현재 선택 상태를 인지하도록 하는 것이 목표다.

## 범위

- 대상: 클럽 앱 노트 화면의 공용 노트 필터 UI
- 유지: 필터 문구와 개수, URL 검색 매개변수, 필터링 결과, 세션 선택, 데이터 요청
- 제외: 아카이브 탭 동작 변경, 서버·BFF·API·데이터베이스 변경, 새로운 색상이나 디자인 토큰 추가

## UI와 상호작용

- 각 필터는 아카이브 탭과 같은 32px 높이의 캡슐형 버튼으로 표시한다.
- 선택하지 않은 필터는 투명 배경, `var(--line)` 외곽선, `var(--text-2)` 텍스트를 사용한다.
- 선택한 필터는 `var(--text)` 배경과 외곽선, `var(--bg)` 텍스트를 사용한다.
- 버튼 간격, 수평 줄바꿈, 컨트롤 글자 크기도 아카이브 데스크톱 탭과 일치시킨다.
- 선택 변경은 기존 `aria-pressed`와 콜백을 그대로 사용한다. 키보드 포커스 외곽선은 기존 전역 접근성 스타일을 유지한다.
- 데스크톱과 모바일은 같은 의미 구조를 사용하며, 좁은 화면에서는 기존처럼 다음 줄로 자연스럽게 감싼다.

## 구현 경계

노트 필터를 렌더링하는 공용 프런트엔드 컴포넌트에서 버튼의 시각 상태를 결정한다. 필터 상태나 라우트 데이터 흐름은 바꾸지 않는다. 이번 요청에 필요하지 않은 공통 탭 추상화나 아카이브 컴포넌트 리팩터링은 하지 않는다.

## 검증

- 컴포넌트 테스트에서 초기 선택 필터와 다른 필터의 외곽선·배경·텍스트 스타일을 확인한다.
- 다른 필터를 선택했을 때 `aria-pressed`와 검은 선택 상태가 함께 이동하는지 확인한다.
- 노트 화면을 데스크톱과 모바일 크기에서 열어 줄바꿈, 선택 가시성, 포커스 상태를 확인한다.
- 프런트엔드 린트, 테스트, 빌드를 실행한다.

## 통합

변경은 `codex/notes-filter-archive-parity` 브랜치에서 완료하고 검증 후 로컬 `main`에 통합한다. 원격 푸시와 배포는 범위에 포함하지 않는다.
