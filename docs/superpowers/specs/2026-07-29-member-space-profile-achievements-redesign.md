# ReadMates 내 공간 프로필·독서 성취 리디자인

작성일: 2026-07-29
상태: 디자인 승인 완료, 작성본 검토 대기

## 1. 요약

`/clubs/:clubSlug/app/me`를 출석 흐름 중심 화면에서 프로필과 누적 독서 성취 중심의 개인 공간으로 다시 구성한다.

현재 화면의 회차별 `최근 참여 흐름`은 출석 미확정 상태를 크게 노출해 `함께한 모임 3회`와 `최근 6회 중 0회`처럼 서로 충돌하는 인상을 만든다. `내 책별 기록 전체 보기`는 아카이브가 이미 제공하는 책·회차 탐색과 역할이 겹친다. 질문, 서평, 책 목록 또한 클럽 노트와 아카이브에서 확인할 수 있으므로 내 공간에 다시 모으지 않는다.

내 공간은 다음 두 질문에 빠르게 답한다.

1. 현재 이 클럽에서 나는 어떤 프로필과 멤버십 상태인가?
2. 지금까지 함께한 모임과 독서 성취가 얼마나 쌓였는가?

방문자 모드는 `Operate`다. 멤버는 자신의 프로필을 확인·수정하고 계정 관리로 이동한 뒤, 누적 독서 성취를 짧게 회고한다.

## 2. 목표

1. 프로필과 계정 관리 진입점을 첫 번째 구획에 둔다.
2. 참여 이력과 독서 성취를 정확한 누적 값과 자연스러운 회고 문장으로 보여준다.
3. 출석 미확정 상태가 성취를 부정하거나 데이터가 충돌하는 인상을 만들지 않게 한다.
4. 아카이브, 클럽 노트, 계정 관리와 내 공간의 역할 중복을 줄인다.
5. 일반적인 통계 대시보드 대신 ReadMates의 차분한 개인 독서 책상 인상을 유지한다.
6. 데스크톱과 모바일에서 같은 의미 순서, 충분한 조작 영역, 명확한 권한 상태를 제공한다.

## 3. 비목표

- `/app/archive`, `/app/notes`, `/app/me/records`의 전면 리디자인 또는 route 삭제
- 질문, 서평, 한줄평, 책 목록을 내 공간에 다시 노출
- 회차별 출석 원장 또는 최근 참여 타임라인 제공
- 올해 단위 통계, 연도 필터 또는 과거 연도 탐색
- 다른 멤버, 클럽 평균, 순위, 배지, 연속 참여 또는 경쟁 요소
- 프로필 이미지 업로드 기능
- 이메일, 계정명, 멤버십 정책, 로그아웃 또는 탈퇴 동작 변경
- 새로운 서버 API, 데이터베이스 테이블 또는 Flyway migration
- 멤버 홈과 이번 세션의 준비 흐름 변경

## 4. 선택한 방향

### 4.1 선택: 프로필 + 누적 독서 요약

프로필을 최상단에 두고, 누적 참여와 독서 성취를 한 편의 짧은 개인 연보처럼 이어 보여준다.

장점:

- 프로필·계정 관리와 독서 성취라는 내 공간의 두 역할이 분명하다.
- 회차별 상태를 반복하지 않아 아카이브 및 출석 화면과 겹치지 않는다.
- 카드 묶음보다 문장, 선, 여백을 중심으로 ReadMates의 편집적 톤을 유지한다.
- 현재 프로필 및 개인 journey summary를 재사용해 서버 변경 없이 구현할 수 있다.

### 4.2 제외: 프로필 + 참여 원장

연도 아래 확인된 참여 회차를 행 단위로 나열하는 방식이다. 정확한 회차 확인에는 유리하지만 다시 출석 관리 화면처럼 보이고, 아카이브와 역할이 겹치므로 제외한다.

### 4.3 제외: 프로필 + 관리 허브

프로필, 멤버십, 로그아웃 등 설정 항목을 상단 목록으로 모두 펼치는 방식이다. 계정 작업은 빠르지만 일반적인 설정 대시보드에 가까워지고 독서 성취의 정서적 위계가 약해지므로 제외한다.

## 5. 정보 구조

데스크톱과 모바일은 다음 순서를 공유한다.

```text
내 공간
├─ 내 프로필
│  ├─ 이니셜 아바타
│  ├─ 표시 이름
│  ├─ 클럽명 · 멤버십 상태 · 함께한 기간
│  ├─ 프로필 수정
│  └─ 계정 관리
└─ 함께 읽어 온 기록
   ├─ 누적 값 기반 회고 문장
   ├─ 참여 확정 횟수
   ├─ 완독
   ├─ 질문(1개 이상일 때)
   ├─ 서평(1개 이상일 때)
   └─ 멤버십 시작 월
```

다음 기존 요소는 `/app/me`에서 제거한다.

- `나의 서재` 제목과 참여 흐름 설명
- `전체 기록 / 함께한 모임 N회` 단독 영웅 구획
- `최근 참여 흐름` 회차 타임라인
- 연속 참여와 다음 참여 안내
- `내 책별 기록 전체 보기`
- 페이지 하단 별도 `계정` 및 로그아웃 구획

`/app/me/records` route는 이번 범위에서 삭제하지 않는다. 다만 내 공간에서는 진입 링크를 제공하지 않으며, 책과 회차 탐색의 대표 목적지는 아카이브로 유지한다.

## 6. 프로필 구획

### 6.1 표시 정보

프로필 구획은 다음 정보를 사용한다.

- 아바타: 표시 이름의 첫 유효 글자를 사용한 기존 계정 이니셜 표현
- 표시 이름: `displayName`
- 클럽명: `clubName`
- 멤버십 상태: 기존 `membershipIdentityLabel` 매핑
- 함께한 기간: `joinedAt`과 현재 월의 차이

프로필 이미지 URL은 현재 `/api/app/me` 계약에 없으므로 새 이미지 UI나 업로드 affordance를 만들지 않는다.

### 6.2 프로필 수정

`프로필 수정`은 별도 페이지로 이동하지 않고 현재 프로필 구획 아래에 표시 이름 편집 영역을 펼친다.

- 입력값은 현재 표시 이름으로 시작한다.
- 저장은 기존 `PATCH /api/me/profile`과 오류 코드 매핑을 재사용한다.
- 저장 중에는 저장 버튼을 비활성화하고 중복 요청을 막는다.
- 성공하면 프로필 표시 이름, 전역 계정 메뉴, 인증 상태를 갱신한다.
- 실패하면 입력값과 편집 상태를 유지하고 control 가까이에 `role="alert"` 오류를 표시한다.
- 취소하면 저장하지 않고 편집 영역을 닫는다.

`canEditOwnProfile`이 거짓인 상태에서는 수정 버튼을 렌더링하지 않는다. 읽기 전용 프로필 정보와 `계정 관리`는 계속 제공한다.

프로필 API 호출과 인증 상태 갱신은 route/controller 계층이 소유한다. UI는 `canEditProfile`, 현재 데이터, update callback만 받아 렌더링한다. `/app/me`와 `/app/me/settings`가 같은 저장·오류 처리를 사용하도록 기존 `ProfileNameEditor`와 프로필 update controller 경계를 재사용하거나 공통화한다.

### 6.3 계정 관리

`계정 관리`는 기존 `/app/me/settings`로 이동한다. 다음 항목은 상세 계정 화면과 계정 메뉴에 유지한다.

- 이메일 및 계정명
- 멤버십 상세 상태와 클럽 정보
- 로그아웃
- 클럽 탈퇴

클럽 탈퇴 같은 파괴적 동작은 내 공간 최상단에 직접 노출하지 않는다.

## 7. 누적 독서 성취

### 7.1 데이터 범위

독서 성취는 현재 클럽의 현재 멤버십 누적 값만 사용한다.

- 참여: `MyJourneySummary.attendedSessionCount`
- 완독: `MyJourneySummary.completedReadingCount`
- 질문: `MyJourneySummary.questionCount`
- 서평: `MyJourneySummary.reviewCount`
- 시작 월: `MyPageResponse.joinedAt`

`MyPageResponse.recentAttendances`는 이 화면의 표시나 회고 문장 계산에 사용하지 않는다. 출석 미확정, 불참, 가입 전 회차를 최근 성취처럼 다시 계산하지 않는다.

시안에서 탐색한 `2026 · 나의 독서` 같은 연도 표기는 사용하지 않는다. 현재 summary는 연도별 값이 아니라 누적 값이므로 최종 label은 `함께 읽어 온 기록`으로 고정한다.

### 7.2 회고 문장

회고 문장은 서버가 준 누적 값을 클라이언트 pure model에서 결정한다. 일부 page 길이 또는 최근 출석 배열로 전체 값을 추정하지 않는다.

기본 규칙:

- 참여 0회: `첫 모임부터 이곳에 독서 기록이 쌓여요.`
- 참여 N회, 완독 0권: `N번의 모임을 함께했어요.`
- 참여 N회, 완독 M권: `N번의 모임에서 M권을 끝까지 읽었어요.`

한국어 수사는 별도 숫자 사전으로 무리하게 확장하지 않는다. 1~3처럼 현재 제품 copy에서 자연스럽게 검증할 수 있는 범위를 제외하면 숫자 표기를 사용해 긴 범위에서도 정확성을 우선한다.

보조 설명은 경쟁이나 연속 참여를 암시하지 않는 한 문장으로 제한한다. 기본 문구는 `함께 읽는 시간이 차분히 쌓이고 있습니다.`다.

### 7.3 지표 표시

- `함께한 모임`과 `완독`은 핵심 성취이므로 0도 표시할 수 있다.
- `질문`과 `서평`은 1개 이상일 때만 표시한다.
- 표시 항목 수에 따라 2~4열을 유연하게 구성한다.
- 모바일에서 항목을 가로 스크롤하거나 잘라내지 않는다.
- 퍼센트, 최근 N회 분모, 연속 참여 수, 출석 미확정 수는 표시하지 않는다.

## 8. 시각·레이아웃

내 공간은 멤버 화면의 `개인 독서 책상` 정체성을 따른다.

- 따뜻한 paper surface, ink 계층, 얇은 rule과 넓은 여백을 사용한다.
- 프로필과 누적 기록은 각각 하나의 semantic section이며, 작은 카드 여러 개로 쪼개지 않는다.
- 아바타의 절제된 mint와 주요 action의 ink-blue만 강조색으로 사용한다.
- 회고 문장이 성취 구획의 시각적 초점이다.
- 지표는 border-box 카드가 아니라 한 줄의 정의 목록과 구분선으로 표현한다.
- 장식적 gradient, glow, glassmorphism, chart, 배지 및 원형 상태 marker를 사용하지 않는다.

데스크톱:

- 프로필 정보는 왼쪽, `프로필 수정`과 `계정 관리`는 오른쪽에 둔다.
- 회고 문장과 참여 확정 요약은 넓은 지면 안에서 비대칭 editorial layout을 사용할 수 있다.
- 지표는 회고 문장 아래 한 줄로 배치한다.

모바일:

- 아바타와 프로필 정보를 먼저 보여주고 action은 그 아래 두 개의 44px 이상 버튼으로 배치한다.
- 회고 문장, 참여 요약, 지표 순으로 단일 열을 유지한다.
- 하단 앱 navigation과 겹치지 않도록 기존 safe padding을 보존한다.

## 9. 상태와 오류

### 9.1 참여 기록 없음

0으로 채운 최근 타임라인을 만들지 않는다.

- 제목: `첫 모임부터 이곳에 독서 기록이 쌓여요.`
- `함께한 모임 0`, `완독 0`은 차분한 초기 값으로 표시할 수 있다.
- 질문이나 서평이 양수면 해당 지표는 숨기지 않는다.
- 이번 세션 행동은 내 공간에 추가하지 않고 멤버 홈과 이번 세션 route가 담당한다.

### 9.2 잘못된 가입 월

`joinedAt`이 비어 있거나 유효한 월로 표현할 수 없으면 함께한 기간과 시작 월을 렌더링하지 않는다. 미래 월을 양수 기간으로 추정하지 않는다.

### 9.3 데이터 로딩 실패

프로필 또는 journey summary 중 하나가 실패하면 다른 값으로 화면을 추정하지 않고 기존 route error boundary를 사용한다. loader는 현재처럼 필요한 요청을 병렬로 수행한다.

### 9.4 프로필 저장 실패

기존 프로필 오류 code를 사용자 문구로 변환한다. 알 수 없는 오류는 기존 일반 저장 실패 문구를 사용한다. 오류가 발생해도 페이지 navigation이나 누적 성취 데이터는 변경하지 않는다.

## 10. 프런트엔드 경계와 데이터 흐름

### 10.1 Loader

`myPageLoader`는 현재처럼 다음 두 요청을 병렬로 수행한다.

1. `/api/app/me`: 프로필, 멤버십, 가입 월
2. `/api/archive/me/journey?limit=1`: 누적 summary

journey item은 렌더링하지 않으며 `limit=1`은 summary 계약을 유지하기 위한 최소 page 요청이다.

### 10.2 Model

pure model은 다음을 담당한다.

- 함께한 기간
- 누적 값에 따른 회고 문장
- 0인 질문·서평 지표 제외
- 멤버십 상태에 따른 프로필 보조 문구
- 빈 상태

React, router, fetch 또는 API client를 import하지 않는다.

### 10.3 Route/controller

route/controller는 다음을 담당한다.

- loader data를 view model로 변환
- 프로필 수정 권한 판단 결과 전달
- 프로필 update 요청, 오류 변환, 중복 제출 방지
- 성공 후 전역 auth refresh와 route revalidation
- `/app/me/settings` link target 제공

### 10.4 UI

UI는 다음 책임 단위로 구성한다.

- `MemberProfileSummary`
- 재사용 가능한 `ProfileNameEditor`
- `ReadingAchievementNarrative`
- `ReadingAchievementMetrics`

UI는 계산된 값과 callback만 렌더링하며 API 또는 auth state를 직접 import하지 않는다. 기존 `ParticipationTimeline`, `ParticipationNudge`, `MemberSpaceAccountActions`, records action은 새 내 공간 composition에서 사용하지 않는다.

## 11. 접근성

- 프로필과 성취를 각각 label이 있는 semantic section으로 구성한다.
- 표시 이름 input은 가시적인 label, 오류 연결, 저장 상태를 제공한다.
- 버튼과 link의 focus indicator를 유지하고 모바일 조작 영역은 최소 44px다.
- 상태나 권한을 색상에만 의존해 표현하지 않는다.
- 200% 확대와 긴 한영 표시 이름에서 겹침이나 가로 스크롤을 만들지 않는다.
- 하나의 DOM 순서를 반응형으로 재배치해 키보드와 시각적 순서를 일치시킨다.
- 새 필수 motion을 만들지 않으며 reduced-motion 설정을 존중한다.

## 13. 범위와 잔여 위험

예상 변경 표면:

- `front/src/pages/my-page.tsx`
- `front/features/archive/route/my-page-route.tsx`
- `front/features/archive/model/my-reading-shelf-model.ts`
- `front/features/archive/ui/my-page/**`
- `front/src/styles/globals.css`
- 관련 model, component, route 및 E2E tests

서버 API, BFF, 데이터베이스, 공개 화면, 호스트 화면, 알림 정책은 변경하지 않는다.

주요 잔여 위험은 프로필 수정 상태가 `/app/me`와 `/app/me/settings`에서 중복 구현되는 것이다. 구현에서는 기존 editor와 update 흐름을 재사용하거나 공통 controller 경계를 만들어 저장·오류·auth refresh 동작이 갈라지지 않게 한다.

또 다른 위험은 기존 E2E가 `내 책별 기록 전체 보기`와 최근 참여 타임라인을 현재 계약으로 검증한다는 점이다. 구현 계획은 삭제된 UI 계약을 새 프로필·성취 계약으로 교체하고 `/app/me/records` 자체의 독립 route 검증은 유지해야 한다.

## 14. 승인된 결정

- 중심 역할: 프로필·계정 관리 진입 + 누적 참여·독서 성취
- 최상단: 프로필 요약, 빠른 표시 이름 수정, 계정 관리
- 계정 상세: 이메일, 계정명, 멤버십, 탈퇴는 기존 상세 화면에 유지하고 로그아웃은 기존 계정 메뉴에 유지
- 성취 범위: 연도별이 아닌 현재 멤버십 누적
- 표현: 회고 문장 + 유연한 지표 정의 목록
- 제외: 질문·서평 본문, 책 목록, 회차별 타임라인, 최근 참여, 연속 참여, records link
- 출석 미확정: 성취 계산과 화면에서 제외
- 구현 경계: 기존 API와 route-first frontend 구조 재사용, 서버 변경 없음
